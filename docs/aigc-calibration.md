# AIGC 特征与系数标定（0.7.0）

0.7.0 把"量文本"和"给分"拆成两层：`AigcFeatures` 只出 0..1 的特征值，一个权重都不碰；`AigcScorer`
是全部系数的唯一一处。拆完之后系数就不再是"看着顺眼"的数了，它的来历必须能被任何人重跑一遍复现，
所以这台标定台存在的唯一理由就是回答一句话：**这一组系数凭什么。**

头号指标不是召回，是**真人侧余量**（`FPB` 行的 `margin`）：门槛减去真人论文里最像机写的那一句的句分。
`margin < 0` 的系数表一律不合格，无论它在机写侧的召回多好看。这条纪律来自 0.5.4 的实测反证：

```
LEGACY docs=78 sentences=288 mean=0.119 p50=0.088 p90=0.268 p99=0.468 max=0.540 over-gate-0.5=2 margin-at-0.5=-0.040
```

写死权重的 0.5.4 在 78 段真人论文正文上，句分最高 0.540，而 `DuplicateEngine` 拿 0.5 当自编率的门槛，
**余量是负的 0.040** ——已经有 2 句真人在被按"机器腔字符"扣钱了。本轮所有改动都是冲这一条去的。

## 怎么跑

```
pwsh tools/aigc-calibration.ps1
```

整表写到 `artifacts/corpus/aigc-sweep.txt`（189 行：`OVERLAP` 29 / `FEAT` 11 / `GRADE` 11 / `FPB` 6 / `TIER` 24 / `RUNS` 6 / `GRID` 72 / `MARGIN` 5）。
换语料用 `-Corpus` / `-Frames` / `-Cartoon`，改输出用 `-Out`。脚本只往 `artifacts/build/aigc-check/`
里写 class，既不清 `artifacts/build`，也不跑 `tools/test-host.ps1`（那条目录归检索链路用）。
标定台每次都重编，app 类缺了才全量补编，所以表里的数不可能来自旧 class。

跑回归是另一条命令，不经过本脚本：

```
javac -encoding UTF-8 -classpath artifacts/build/aigc-check/classes -sourcepath tests -d artifacts/build/aigc-check/test-classes tests/AigcRegression.java
java -Dfile.encoding=UTF-8 -cp "artifacts/build/aigc-check/test-classes;artifacts/build/aigc-check/classes" com.rikkahub.wordlite.AigcRegression
```

## 语料

| 代号 | 文件 | 是什么 | 能不能当标定物 |
| --- | --- | --- | --- |
| H1 | `tests/corpus/real-prose.txt` | 真实学位论文正文，每行一段：78 段 / 288 计分句，但只有 1 篇论文、1 位作者 | **唯一的真人负例**，`margin` 只由它决定 |
| M1 | `LocalRewriter` 的改写体 | 本仓库离线降重写出来的句子 | **明确不用**：与同段真人句的配对胜率 6.4%，低于抛硬币，它比真人还不像机器 |
| M2 | `tests/corpus/aigc-frames.txt` + H1 的真人句 | 按"总分总 + 首先/其次/最后"骨架把真人句拼起来，74 篇 | 只能当**旁证**：分离度来自构造（见下面 `OVERLAP`） |
| M3 | `tests/corpus/aigc-cartoon.txt` | 20 段漫画式机写稿（每段九十字上下） | 只能测"像不像想象中的机器腔"，每段过不了 400 字样本门槛，所以另有 `LONG3` |
| 钉子户 | `tests/corpus/aigc-hard-human.txt` | `MARGIN` 行挑出来的真人最高五句 | 回归夹具：`AigcRegression.hardHuman()` 直接读它 |

产物第一段的 `OVERLAP` 行不是日志，是**免责条款**：骨架表 30 个词里 28 个本身就命中打分特征
（`综上所述` 同时进 `TEMPLATE` 和 `CONNECTIVE`，`通过`/`可以` 在连接词表里）。所以 M2 的召回是
"用这套词表造的稿子，用这张词表的系数打分"的一致性检查，不是真实召回率。这句话必须跟着数字走，
`AigcScorer` 的注释、本文件的表格标题、`GRADE` 行都各写了一遍。

## 反证基准：权重与误报成本几乎成反比

`LEGACY-FEAT` 行复现的是 0.5.4 那套写死权重的触发率（每千句），除了下面单独说的破折号那一条，
其余七条与重构后的 `FEAT` 行逐条相等，说明这次重构没有改"量文本"的那一头，只改了怎么加权：

| 0.5.4 那条证据 | 真人侧触发 /千句 | 0.5.4 单条加的分 |
| --- | --- | --- |
| 实词多样度低 | 243.1 | 0.08 |
| 破折号使用 | 232.6 | 0.088（`PUNCT` 0.11 的 0.8 档） |
| 并列排比密集 | 222.2 | 0.12 |
| 句长突发度低 | 187.5 | 0.12 |
| 分号衔接并列分句 | 152.8 | 0.066（1 个）/ 0.11（≥2 个） |
| 连接词密度偏高 | 72.9 | 0.18 |
| 引号密度偏高 | 3.5 | 0.066 |
| 模板句式 | 20.8 | 0.30（第 3、4 条命中各 0.105） |
| 程度副词/评价词堆叠 | 0.0 | 0.16 |
| 字符二元组熵偏低 | 0.0 | 0.08 |
| 句首结构重复 | 0.0 | 0.12 |

触发最凶的三条（多样度 0.08 + 破折号 0.088 + 排比 0.12 = 0.288，按 `PUNCT` 全额 0.11 算是 0.31）加起来比
模板句式单条的 0.30 还高，而模板恰恰是真人侧最稀有的一条（20.8/千句）。**权重高低与"在真人论文里造成
误报的概率"几乎成反比**，`max=0.540` 就是这么叠出来的。本轮把系数压成四组：唯一敢给到 0.35 的是套话组，
触发最凶的节奏与词汇整体压在 0.15 与 0.10，且组内取最强、组间相加，同组的多条证据不再叠成一份。

| `PUNCT_QUOTE` | 节奏 | 3.5 | 0.0 | −3.5 | 0.000 / 0.600 | 0.150 | ORDER-ONLY |
| `BURST` | 节奏 | 187.5 | 124.5 | **−63.0** | 0.478 / 0.478 | 0.100 | ORDER-ONLY（反向证据） |
| `PUNCT_SEMICOLON` | 节奏 | 152.8 | 113.2 | **−39.6** | 0.600 / 0.600 | 0.100 | ORDER-ONLY（反向证据） |

两条要单独说：

- **`PUNCT_DASH` 的真人侧数字从 232.6 变成 253.5**。这不是把检测调松了：0.5.4 与 `LEGACY-FEAT` 用的是
  一串 `else if`，一句里既有破折号又有分号时只记分号那一笔；本版按特征各自独立数，破折号不再被前面的
  分支吃掉。所以两个数都对，只是口径不同，别拿它们互相校验。
- **`BURST`、`PUNCT_SEMICOLON` 与机写弱标签负相关**（−63.0、−39.6）。骨架拼接出来的稿子比真人更"不平"，
  分号也少。这不是它们没用的证据（真人爱用分号却是好事），但它绝不配上"机写特征"的名头，所以压到
  节奏组最低一档，0.7.1 要动标点画像时从这里开刀。
## 台一：FPB 真人误报预算（唯一有外部效力的一台）

按 v1 表在 H1 上逐句打分：

| 组 | 组系数 | 真人侧该组把整句推到可疑的概率 |
| --- | --- | --- |
| 套话 | 0.350 | 0.0208（6/288） |
| 句式框架 | 0.200 | 0.0729（21/288） |
| 节奏 | 0.150 | 0.6181（178/288） |
| 词汇 | 0.100 | 0.2431（70/288） |

```
FPB  gate=0.45 human-mean=0.077 human-p50=0.067 human-p90=0.175 human-p99=0.281 human-max=0.366 margin=+0.084 over-gate=0/288 budget=0.05 docs-flagged=0/78
FPB  同表机写侧 machine2-mean=0.296 p50=0.308 p90=0.537 max=0.708 over-gate=47/265
```

对照 0.5.4 的 `p99=0.468 max=0.540 margin=-0.040`：真人最高句分从 0.540 掉到 0.366，余量由 **−0.040
变成 +0.084**，288 句真人句子里 0.5 档过线的从 2 句变成 0 句。同一张表在 M2 上的过线率是 17.7%
（47/265 句）——这余量不是靠"什么都不报"换来的。
## 台二：TIER 双门槛（`TIER` / `RUNS` 行）

产品口径的档位要**同时**满足连续度（`longestRunSentences ≥ 2/3`）与绝对量（`flaggedChars ≥ 200/400`）。
`TIER` 行是逐句版的同一套判据，`RUNS` 行是"落在连续 k 句里的字符占比"：

| 门槛 | 连句 | 字数 | 真人 | M2 | M3 |
| --- | --- | --- | --- | --- | --- |
| 0.35 | ≥1 | 200 | 0/78 | 8/74 | 0/20 |
| 0.35 | ≥2 | 200 | 0/78 | 6/74 | 0/20 |
| 0.35 | ≥3 | 200 | 0/78 | 0/74 | 0/20 |
| 0.45 | ≥1 | 200 | 0/78 | 2/74 | 0/20 |
| **0.45** | **≥2** | **200** | **0/78** | **0/74** | **0/20** |
| 0.25 | ≥1 | 200 | 0/78 | 24/74 | 0/20 |
| 0.25 | ≥1 | **0（撤掉字数门槛）** | **7/78** | 72/74 | 10/20 |
| 0.30 | ≥1 | **0（撤掉字数门槛）** | **2/78** | 70/74 | 10/20 |
| 0.35 | ≥1 | **0（撤掉字数门槛）** | **1/78** | 62/74 | 6/20 |
| 0.45 | ≥1 | **0（撤掉字数门槛）** | 0/78 | 44/74 | 3/20 |

`RUNS` 行是同口径的字符占比，看真人侧更细：门槛 0.25 时真人有 3.4% 的字符落在"≥1 连句"里，但
**落在 ≥2 连句里的是 0.0%**；0.30 时 0.8% → 0.0%；0.45 时 0.0% → 0.0%。真人的高分句是**孤立**的，
机写骨架稿的高分句是成片的，区间聚合买的就是这个差别。

两张对照组必须放在一起读，否则会误以为双门槛是白加的：

- 只放松连续度（≥1 即可）：真人侧在 0.45 门槛上还是 0/78，**因为 v1 表已经把真人最高句分压到 0.366**，
  没有一句过线。这不是"连续度门槛没用"，是这一档量不出它的用处。
- 所以另外加了探针档：把门槛放到真人最高分以下（0.25 / 0.30 / 0.35）再把字数门槛一起撤掉，
  真人侧立刻 7/78、2/78、1/78。**双门槛要挡的就是这几篇**：只要有一句过线就把整段点名成待复核，
  真人论文里"某一句用了排比 + 一个套话"是常事，代价就是这几段真人正文被拉去复核。
- M3 那一列在带字数门槛的行里恒为 0/20，不是漏检：20 篇稿子每篇只有九十字上下，绝对够不到 200 字的
  可疑字数，产品口径下它们全停在"样本不足"。`LONG3` 行把每 5 篇接成一篇跨过 400 字样本门槛再跑一次：
  4 篇里 3 篇落在观察档，可疑字符合计 160，**没有一篇到复核档**。

```
RULE 产品口径（区间分为字符加权均值 + 区间过线）档位分布 真人=75/2/1/0/0 machine2=70/0/3/1/0 machine3=20/0/0/0/0
LONG3 每 5 篇漫画稿接成一篇 docs=4 产品口径档位分布 1/0/3/0/0 可疑字符合计 160
```

（档位顺序：样本不足 / 一般 / 观察 / 复核 / 成段。）真人侧 75 段停在样本不足（单段正文本来就
不到 400 字）、2 段一般、1 段观察，复核与成段两档在 78 段真人正文上是 0 段。

## 台三：GRID 系数网格（人机双向同屏）

读数规则先说死：**先在 `margin ≥ +0.05` 且 `h-flag = 0` 的行里挑，再在剩下的行里取召回最大的一行**。
`paired-win` 只作旁证（M2 被构造偏置污染）。下面是沿套话组扫的一段，节奏与词汇固定：

```
GRID cliche=0.250 frame=0.200 rhythm=0.150 lexis=0.100 human-max=0.316 margin=+0.134 h-flag=0/78 m2-over=9.8%  m3-over=3.6%
GRID cliche=0.300 frame=0.200 rhythm=0.150 lexis=0.100 human-max=0.341 margin=+0.109 h-flag=0/78 m2-over=15.8% m3-over=5.4%
GRID cliche=0.350 frame=0.200 rhythm=0.150 lexis=0.100 human-max=0.366 margin=+0.084 h-flag=0/78 m2-over=17.7% m3-over=5.4%   <- 落表
GRID cliche=0.400 frame=0.200 rhythm=0.150 lexis=0.100 human-max=0.391 margin=+0.059 h-flag=0/78 m2-over=24.2% m3-over=7.1%   <- 预算内最优
GRID cliche=0.350 frame=0.200 rhythm=0.200 lexis=0.100 human-max=0.416 margin=+0.034 h-flag=0/78 m2-over=21.9% m3-over=5.4%
```

```
PICK best-in-budget cliche=0.400 frame=0.250 rhythm=0.150 lexis=0.100 margin=+0.059 h-flag=0 m2-over=24.5% m3-over=7.1%
```

**没有采纳 `best-in-budget`，退一档落在 0.350。** 三条理由，写在这里免得下一个人以为 0.40 是漏了：

1. 多买的那 6.5 个百分点召回全部落在 M2 上，而 M2 就是拿 `TEMPLATE`/`CONNECTIVE` 那两张词表拼出来的
   （`OVERLAP` 行）。在自己造的题上多拿分不算本事。
2. 真人侧只有 1 篇论文的 288 句，`+0.059` 的余量等于"最像机写的真人句子离门槛还有 3.6 个百分点半格"，
   换一位爱写排比的作者就可能翻过去。
3. 节奏组往上抬（0.20）余量直接掉到 `+0.034`，说明真正贵的不是套话而是节奏——这也是为什么本轮把
   节奏组的门面系数按 0.15 封顶，而不是按召回需要抬。

**所以套话组的取值上限是 0.40，落表 0.35 是主动退的一档，不是标定出来的拐点。**

## 定值还是定序：为什么版本号必须叫 `v1-order-only`

`GRADE` 行把判据写成可执行的形式，不靠自觉。一条特征允许由 GRID 的拐点**定值**，必须三条同时成立：

1. `overlap = false`：它不在骨架表的词表里，机写侧的高触发不是被自己构造出来的；
2. `p_M − p_H > 0`：机写侧触发率确实高于真人侧；
3. `p_H ≤ 5/千句`：真人侧几乎不触发，误报预算才有余量可言。

代进本轮实测：`TEMPLATE` 满足 2、3 但 `overlap = true`；`CONNECTIVE`、`INTENSIFIER` 同样栽在
`overlap`；`BURST`、`PUNCT_SEMICOLON`、`PUNCT_QUOTE` 栽在第 2 条（差值是负的）；`OPENING`、`ENTROPY`
两头都是 0（无信息）；`PARALLEL`、`DIVERSITY`、`PUNCT_DASH` 栽在第 3 条（真人侧 222、243、253/千句）。
**11 条特征，没有一条够格定值**，所以 `GRADE` 行 11 条全是 `ORDER-ONLY`：

```
GRADE TEMPLATE  ORDER-ONLY overlap=true human-rate=20.8/1000 machine-minus-human=+688.6
```

结论直说：**这张表的真实身份是"按实测触发率定序 + 按真人误报预算封顶"的一组保守常数，
`AigcScorer.VERSION = "v1-order-only"`。** 它不是标定值，本文档不出现"已标定"这个说法，直到有真标注
语料为止（那时候才配叫 `cal-*`）。系数表旁边每条注释都带着它的真人侧触发率与 `ORDER-ONLY` 标记，
`AigcScorer.check()` 还钉着两条纪律：四组系数加和 ≤ 1.0（实测 0.8），单条系数 < `SEGMENT_FLAG_GATE`。

标定口子只有测试与标定台能用：`AigcScorer.overrideCoefficients()` / `restoreCoefficients()` 是
**包级私有**（照 `TextCorpus.overrideThresholds` 的先例），产品路径拿不到它们，`current(family)`
永远发默认表。GRID/TIER 那些候选系数就是靠这对方法扫的，扫完必还原。

## 口径不变式（改了系数也不许动这四条）

1. `Result.rate` 仍是**字符加权的句分均值**，`Σ 句分 × 有效字符 / Σ 有效字符`，定义一个字没改。
2. 区间是"分区不挑选"的视图：每个计分句恰好落进一个区间，低分句也自成区间。于是
   `Σ segment.chars == comparedChars` 与 `Σ segment.score × chars / Σ chars == rate` 是恒等式，
   回归里逐条断言。加成只进档位，不进任何百分比。
3. 双门槛：`flaggedChars`（绝对量 200/400）与 `longestRunSentences`（连续度 2/3）**相与**，只满足
   比例就降一档；`run=1` 的句子永远成不了档。
4. 有效字符 `< 400` 只给"样本不足"，不给比例；0 个计分句也算样本不足（0.5.4 在这里会印 0.00%，
   与 `docs/oss-algorithms.md` 那条纪律冲突，本版改掉）。

## 还没解决的

- **真人侧只有 1 篇学位论文、1 位作者。** 零误报是"这一位作者不写连续排比段"的零误报。爱写排比的作者
  会被冤枉，这个比例现在无法量化。这是 `margin` 这个数字全部的含水量。
- **英文族没有语料，只有平移。** `AigcScorer.defaults(AigcFamily.LATIN)` 的版本号是
  `v1-order-only+latin-derived`，明确声明未标定。多样度下限分族（0.78 / 0.62）是两条各自能过活的线，
  不是标定出来的对应关系。
- **混排折扣 `MIXED_DISCOUNT = 1.00`** 是"先不惩罚"，中英混排的稿子本轮没有语料，留给 0.7.1。
- **召回列一律是弱标签一致性检查**，不是真实召回率。跨生成器、跨语言、抗复述攻击的泛化本来就差
  （见 `docs/oss-algorithms.md`），所以产品口径永远是"风格倾向 + 建议复核"，档位不叫"AI 比例"。
- **短文量不到档位。** 400/200 字的绝对门槛意味着一整节不足 400 字的稿子只能停在"样本不足"，
  `LONG3` 行就是这个现象的直白读数。
- **`h-flag = 0` 在 GRID 的 72 行里恒为 0**，说明"整段被点名"这个指标在真人侧已经饱和，往后调系数
  只能看 `margin` 与 `human-max`，别再拿 `h-flag` 当刹车。
