# 段落级风格统计实测：AUC 到了 0.85 之上，2/千段那条线还差什么（2026-10-09）

这一页接着 `docs/aigc-detection.md` 往下量：那一页量的是"概率类信号换哪一条都不行"，这一页量的是
**把计分单位从一句换成一段（120~656 字），换成分布型风格统计（句长分布、连接词与枚举密度、人称、数字与单位写法密度、
汉字类符形符比……）之后，能不能同时满足 AUC(机器>真人) ≥ 0.85、真人误报 ≤ 2 段/千段、同一个阈值上机器召回不为 0。**

结论：**换判别面确实把排序能力顶上去了——同一篇原文的人写段对机写段，AUC 最高 0.8793（随包那条判据在同一产品域上是 0.271）。
工作点也不再是空的：最好的几条组合在真人误报 2/千段附近能抓到 1.4%~6.7% 的机器段，不是上一轮那种"抓住 0 句"。
但三条要同时成立还是差一截**：贴线那条 AUC 0.8514 只高出 0.0014；真人误报 1.81/千段的 95% 区间是
0.96~3.44/千段，也就是说 4,961 段真人的分母**量不出**"≤2/千段"这件事；而在出厂那条审计自己用的标注稿上
（`tests/corpus` 的 H1/H2/H3/X1/HH 对 M-RAW/M-EVADE/M-DOMAIN，125 真人段 / 49 机器段），
这两条最好组合的机器召回都是 **0/49**。所以 `AigcScorer.calibrated()` 与 `AigcNgramModel.calibrated()` 继续是 false，
界面与报告一个 AIGC 百分比都不印，版本停在 2.x。

## 0. 怎么复跑

```
py tools/aigc-para-probe.py prep    # 切段、配对、算 35 个特征 → artifacts/aigc-para-probe/units.jsonl
py tools/aigc-para-probe.py sig     # 逐特征：拟合 AUC、五个外域方向一致性、头部有没有召回
py tools/aigc-para-probe.py fit     # 组合、两套阈值定法、真人误报与同一阈值上的机器召回
py tools/aigc-para-probe.py check   # 16 条断言：串档/许可/长度/重算一致/随包判据指纹没变
```
读数清单（只有计数与数，一段原文都不进仓库）：`tests/corpus/aigc-para-probe-summary.json`。
`fit` 打印的每个数都在那份清单里，`check` 会拿清单里的规格把最佳候选原样重建再算一遍，对不上就红。

## 4. 那两条最接近的，各差什么

**字面过线那条**（`sent_std` + `sent_cv` + `ttr_cjk` 的秩平均，阈值只看拟合档真人）：AUC 0.8514、
真人误报 1.81/千段（9 段越线 / 4,961 段）、同一阈值机器召回 1.4%（逐台：deepseek-v3 2.6%、gemini-2.5-flash 1.6%、
gpt-4o 1.1%、qwen-max 0.7%）。加"不足 4 句的段落一律不判"的护栏后误报 1.41/千段、召回不掉。四个不能上线的理由：

1. AUC 只超线 0.0014，配对留出 1,981 对，这点余量在重切一遍的噪声里。
2. 1.81/千段的 95% 区间 0.96~3.44：**4,961 段真人量不出"≤2/千段"**。要把这条线钉到 ±0.5 个千分点，
   真人侧要 2 万段以上，不是 5 千段。
3. 误报在长度带上不匀：480~656 字那一格 12.41/千段（7 段 / 564 段），120~479 字三格是 0.00 / 0.00 / 0.76。
   全局一个阈值盖住了那一格。
4. T3 上机器召回 0/49：产品自己那批标注稿（含"要求规避风格"那档）一段都没抓到。

**AUC 与召回最好看那条**（8 条特征逻辑回归，C 由拟合档内部按篇三折自己选到 0.5，折内 AUC 0.8845）：
AUC 0.8793、召回 9.9%，但真人误报 4.23/千段（阈值换成 cal 是 2.22，代价是召回掉到 6.7%），
且它靠的 `digit_p100` 在 News/SEO 上符号是反的——符号是"学术这一池"给的，换域就翻。T3 同样 0/49。

**并尾投票**（数"有几条特征同时越过拟合档真人的 99 分位"）是本轮专门为了"单条尾巴压不过真人尾分位"设计的，
它确实把 T3 的召回顶到 4.1%（唯一在 T3 上抓到东西的一条），代价是 AUC 只有 0.7279，够不着 0.85。

## 5. 一句话给下一个读的人

段落级这一档把上一轮"排序好但工作点为空"的形状**部分**解开了：秩平均 / 逻辑回归能靠联合尾部把召回从 0 拉到百分之几。
但剩下的两件事没有解开，而且看起来不是再挑挑特征能解开的：
**真人分布的 99.8 分位附近，机器段只有百分之几的质量**（要的是那一点质量，不是排序面积），
以及 **5 千段真人的分母量不出 2/千段**。

## 6. 要往下走，前置是这两条（可判定）

1. 真人侧按篇再扩到 **2 万段以上**（现在 H2 4,455 段 / 3,031 篇 + VAL 2,811 段 = 7,266 段可量），
   否则"≤2/千段"永远只有 ±1.5 个千分点的分辨率，任何"过线"都是掷硬币。
2. 机器侧要一批**没读过判据、也不是改写现有真稿**的段落稿：本轮 VAL 是同篇改写（内容全对齐，最干净，
   但也是最好判的一档），T3 是读过判据的代理生成稿（最难，最好组合 0/49）。
   这两端中间的"自然交上来的机器段"没有样本，而产品真正要抓的是中间那一档。

## 7. 随包判据一个字节都没动

`AigcScorer.java`、`AigcNgramModel.java` 与 `app/src/main/assets/aigc/` 那三份（`aigc-model.tsv`、
`aigc-zh-freq.tsv`、`aigc-zh-weights.tsv`）的 SHA-1 记在 `tests/corpus/aigc-para-probe-summary.json` 的
`shipped_guard` 里，`check` 第 15 条逐条比；两个 `calibrated()` 照旧 false，`AigcDetector.verdict()` 照旧"判据未标定"。
本轮没有加第 34 条风格特征，没有动阈值，没有把上面任何一条候选接进应用。

## 8. 分母这一轮怎么做大（2026-10-09 追加，进行中）

§4 第 2 条说得很清楚：4,961 段真人量不出"<=2 段/千段"。这一节只把两件事写死：
**误报读数要配一个分辨率**，以及**分母做到多大才算数**。

### 8.1 误报读数必须带分辨率

误报是个计数。设分母 n 段、读数 r 个/千段，期望越线段数 k = r*n/1000，按泊松近似 95% 区间半宽：

    半宽（个/千段） = 1.96 * sqrt(k) / n * 1000 = 1.96 * sqrt(r * 1000 / n)

在 r = 2/千段这条验收线上取 r=2，代进去：

| 分母（真人段） | 2/千段时的 95% 区间半宽 | 这个分母能不能量出"<=2/千段" |
| --- | --- | --- |
| 4,961（上一轮 VAL 真人 + H2 另一半） | **±1.24/千段** | 量不出：读数 1.81 的区间是 0.96~3.44，2 这条线在区间里两头晃 |
| 16,092（本轮 holdout3 第一族的 HOLD） | **±0.69/千段** | 勉强：2 这条线还在区间内，但 1.3~2.7 都还相容 |
| 20,000（本轮要的线） | ±0.62/千段 | 可以：配合长度带分格看 |
| 30,000 | ±0.51/千段 | 稳：上一版说的"钉到 ±0.5 个千分点"就是这个数 |

同一个公式在 `tools/aigc-corpus3.py report` 里自己算自己印（`fp_resolution_per_1000_at_2`），
不靠人在对话里口算——上一版这里我先把公式写成了 `1.96*sqrt(2/n)*10`，把 16,092 段错报成 ±0.31，
已改正，改完这一族报的是 ±0.69。

### 8.2 第一族落地的实数（PMC 开放获取中文正文）

抓法与上一轮同一把尺，只有两处不同：年份放开到全档（不再卡 2013~2022），每篇封顶从 2 段放到 4 段且仍要求取自不同小节。

| 项 | 数 |
| --- | --- |
| 检索命中 / 逐篇核许可过的篇 | 7,200 / **7,188**（CLOSED 5、NONE 7 整篇丢） |
| 许可分布（按篇） | CC BY 4,146、CC BY-NC-SA 1,533、CC BY-NC-ND 821、CC BY-NC 688 |
| 合用正文段（去重前） | 78,380 |
| 去重后计分段 / 覆盖篇 | **22,470** / 7,103（段长中位 300~520 字窗口内） |
| 按篇三分（段） | FIT 4,619、HOLD **16,092**、SPARE 1,759 |
| 按篇三分（篇） | FIT 1,467、HOLD 5,172、SPARE 561 |

按篇三分的口径：`md5(family|pid)` 稳定哈希，一篇只落一个档，**FIT 里的篇目一次都不参与量误报**。
HOLD 只用来量真人误报，不参与任何定阈值动作。SPARE 是备用样本位（原先留给机器改写，那一路已取消，见 §8.3）。
原文一律留在仓库外 `../aigc-corpus/holdout3/<族>/units.jsonl`；进仓库的是 `tools/aigc-corpus3.py`
与逐篇清单 `tests/corpus/aigc-holdout3-<族>.jsonl`（每篇：URL、DOI、期刊、年份、许可档位、许可字段原文引用、
抓取时间、该篇候选段数与计入段数、落在哪一档），许可原文按篇去重成对照表放在
`tests/corpus/aigc-holdout3-manifest.json` 的 `license_excerpts` 里，清单里没有正文。

### 8.3 机器段不再现造：正例分档与逐档验收

本轮定下：**本机不装任何推理运行时、不下任何模型权重**，因此"用同一批原文让模型改写"这一路取消。
正例改用已缓存的公开数据集，逐档标清它是哪一种，验收里"任一档召回非零"**按档分别给数**，不合并：

| 档 | 是什么 | 条数 | 类型 |
| --- | --- | --- | --- |
| DetectRL-X 通用档 | 同一篇真人原文让人写段与机写段并排（六域 Academic/News/Wiki/Novel/SEO/Webtext × train/test），机写侧 4 家：deepseek-v3、gemini-2.5-flash、gpt-4o、qwen-max | 15,600 对 | **改写档**（同篇配对，长度比 0.70~1.43 的筛子照旧套） |
| RealDet 中文 | 11 家机写稿（4o、Claude-3、ChatGLM-2、DeepSeek、文心一言、通义千问、讯飞星火、360GPT、Baichuan、MOSS、BLOOMz）与人写稿各一堆 | 125,295 机写 + 10,545 人写 | **原生机器稿**（只有题域对齐，不是同篇）——单独一档报，不并进配对留出 |
| HC3 中文 | 同一道题的人答与 ChatGPT 答 | 12,853 | 半配对（同题不同文；套长度比筛子后剩下的才算配对） |
| T3（仓库内标注稿） | 出厂审计那批，生成前读过判据 | 125 真人段 / 49 机器段 | 旁证，最难的一档 |

配对留出仍只认同篇配对那一档；RealDet 那种"同一题域但不同文"的一律单列，
免得靠题材相近白拿 AUC。`AigcScorer.calibrated()` 与 `AigcNgramModel.calibrated()` 在 HOLD 分母过 2 万段
且逐档召回都非零之前继续是 false，界面不印 AIGC 百分比。
