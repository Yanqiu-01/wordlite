# 离线 AIGC 模型（字符 n-gram + 逻辑回归）：做法、量到的数、为什么界面上还是不印百分比

日期 2026-10-09。训练台 `tools/build-aigc-model.py`，权重与字频表在 `app/src/main/assets/aigc/`，
打分器 `AigcNgramModel.java`，回归 `tests/AigcOfflineModelRegression.java`（已进 `tools/test-host.ps1`）。
一句话：**模型做出来了、能在手机上离线跑、也接进了打分链路，但它在真稿上的成绩离出厂门槛差得远，
所以界面上一个 AIGC 百分比都不印。** 下面是数字。

## 1. 为什么换路子

上一轮把启发式特征从 11 条堆到 33 条，重拟合之后留出 AUC 还是 0.657，判据方向在带标注语料上是反的
（`docs/aigc-calibration.md` 第五台）。堆特征这条路已经量过没救，所以这次改成真训一个模型：
字符 2/3/4-gram + 词表 + 逻辑回归，CPU 上训练，导出成文本权重随包，Java 侧纯手写打分，
不引 ONNX、不引新依赖。ROADMAP 3.0.2 那条"手机侧不跑语言模型，用字级 n-gram 频率做困惑度代理"
也一起做了一份字级 1/2/3-gram 频率表 + 滑窗。

## 3. 怎么切的分，怎么选的配置

- 计分句口径照抄应用：`TextCorpus.normalize` 折叠 → 去空白与不可见字符 → 按 `TextCorpus.sentences`
  的句号/问号/分号/换行切句 → 有效字符 8~300 才要（8 就是 `AigcDetector.MIN_SENTENCE_CHARS`）。
  Python 侧把 `fold`/繁简表/切句都镜像了一份，繁简表直接从 `TextCorpus.java` 里解析，两边共用一张表。
- 切分按**来源分组**：同一条问答、同一篇摘要（标题作组号）、同一条短句改写落进同一份，
  十等分取第 0 份留出。这样"原句 + 它的 ChatGPT 改写"不会一半在拟合一半在留出。
- 特征：字符 2/3/4-gram，`min_df` 过滤词表 → 逻辑回归 → 按 |系数| 剪到 20,000 条 → 在剪后的子集上
  **重新拟合一次**。重拟合是必须的：手机侧只带得起导出表，分数要在导出表上归一化，
  Java 才可能算出同一个数（`句分 = sigmoid(截距 + Σ(1+ln 次数)·w / ‖x‖₂ + 偏置)`）。
- 选配置只看公共侧：用"留出里学术配对档（prhpp / prhpp_te）最差那一档的 AUC 最大"这一条挑，
  因为那是公开语料里唯一一份"同一位作者同一篇稿，人写原稿 vs ChatGPT 润色"的配对档。
  **真稿那份独立留出只在读门槛的那一步读，没参与任何配置选择。**

六组配置的公共侧成绩（`artifacts/agent-aigc-offline/train-summary.json`）：

| 配置 | 计分句 | 词表 | 导出特征 | 拟合 AUC | 公共留出 AUC | 学术配对档 |
| --- | --- | --- | --- | --- | --- | --- |
| A-all（全用，2-4 gram） | 275,789 | 107,470 | 20,000 | 0.9776 | 0.9663 | 0.762 |
| B-prhpp-only（只用学术配对档） | 13,897 | 8,446 | 20,000 | 0.9443 | 0.8352 | **0.797** |
| C-hc3-only | 179,398 | 85,384 | 20,000 | 0.9879 | 0.9779 | 无（不含学术档，不合格） |
| D-no-hc3（去掉问答，留短句+学术） | 96,391 | 21,405 | 20,000 | 0.9791 | 0.9646 | 0.790 |
| E-formal-mix（去掉口语问答域） | 163,703 | 60,190 | 20,000 | 0.9719 | 0.9574 | 0.788 |
| F-all-1234（加单字） | 275,789 | 110,676 | 20,000 | 0.9782 | 0.9698 | 0.764 |

按规则选中的是 **B-prhpp-only**（`ngram-lr-2026-10-09`）。

## 4. 真稿那份独立留出：不达标

这批是仓库里人工标注好的真稿，一个字都没进训练：真人 H1 学位论文正文 + H2 已发表摘要逐字摘录 +
H3 知网片段 + X1 真人原文轻度润色 + 钉子户句；机器 M-RAW / M-EVADE / M-DOMAIN（M-DOMAIN 与 H1 同领域同主题配对）。
`tests/AigcFeatureAuditRegression` 那套加了一个"段落 ≥120 字"的过滤，所以它的账是 493 真人 / 262 机器；
下面是同一批语料不加那个过滤的计分句数（Python 侧和 Java 应用口径各量一次，Java 是权威）。

| 口径 | 句数（真人 / 机器） | AUC(机器>真人) | 真人误报 @0.45 | 机器侧过线 |
| --- | --- | --- | --- | --- |
| Python（自己的切句） | 624 / 371（共 995） | **0.5580**（段级 0.5757） | 3.205 句/千句 | 0.27% |
| Java（`AigcDetector` 的计分句口径，回归里现算） | 617 / 360 | **0.5611** | 3.24 句/千句 | 0.3% |
| Java（产品打分口径：整段 ≥120 字 + `AigcFeatures.scores`，与标定台同一把尺） | **493 / 262** | **0.5607** | 4.06 句/千句 | 0.0% |

出厂门槛是 **AUC ≥ 0.85** 和 **真人误报 ≤ 2/千句**：三条口径的 AUC 全在 0.56 上下，与抛硬币没有区别；真人误报 3.2~4.1 句/千句，比门槛差一截。两条都不过。
逐档均值（Java 口径）：H1 0.083 / H2 0.092 / H3 0.088 / X1 0.075 / HH 0.100 /
M-RAW 0.083 / M-EVADE 0.073 / M-DOMAIN 0.059 —— 六个真人档里有四个的均值高于两个机器档，方向仍然是反的。

事后算了一下可达工作点：要把真人误报压到 2/千句以内，门槛得抬到 0.4822，
那时**机器侧一句都不过线（0.0%）**。也就是说没有一个可用的工作点。

补一句方向：0.4389 那个数是镜像值。回归里的 Mann-Whitney 实现算的是「真人分 > 机器分」，打印时却标成「机器 > 真人」，本轮把函数签名与打印对齐，真实值 1 - 0.4389 = **0.5611**。门槛与判定逻辑没动，结论不变（依旧远不达标）。

### 为什么公共侧 0.96、真稿上 0.56

（口径提醒：下面的 0.96 是公共留出的最好一档，0.56 是真稿那份独立留出。）

不是代码错了，是学的东西不对，三处证据：

1. 公共留出按来源拆开看就露馅：HC3 问答域 0.975，pangda 短句域 0.985，而学术摘要域只有 0.75~0.80。
   模型主要靠"口语腔 vs 书面腔"这种语域差别分人机的，一换域就没了。
2. B 配置只在"同一篇稿的人写原稿 vs ChatGPT 润色"上训过，公共侧 AUC 0.835，
   说明它学的是**润色留下的痕迹**（虚词替换、句子拉长、"此外/因此"起笔）而不是"机器写的"。
   真稿里 H2 是别人发表过的摘要，没有这些痕迹，被按机器腔打了高分。
3. 机器三档里 M-EVADE（提示词要求规避 AI 风格）在公共侧模型下均值最低（0.073），
   机器一旦不像"想象中的 AI 腔"，模型就认不出。这和上一轮 33 条特征的结论是同一件事。

## 5. 滑窗困惑度代理（3.0.2 那条）：同样不达标

频率表只用**公开真人**语料估（`prhpp` 学术摘要 + HC3 的百科/医学/法律/金融四档）：
单字 2,555 / 二字 20,370 / 三字 10,291 条，log2 概率，查表顺序 三字 → 二字 → 单字 → OOV。
窗口 24 码点、步长 8、不足 12 字的窗口不要，阈值取公共真人窗口的 0.1 分位 = 2.099 bits/字。

| 阈值取公共真人分位 | bits/字 | 模板段落点 | 真人段落点 |
| --- | --- | --- | --- |
| p0.1（出厂取这档） | 2.099 | 0.0% | 0.0% |
| p1 | 2.831 | 0.0% | 0.0% |
| p5 | 3.526 | 1.1% | 1.2% |
| p25 | 4.491 | 15.9% | **31.8%** |
| p50 | 5.186 | 34.1% | **60.0%** |

要求是"模板段落点 ≥ 90% 且真人段整段不进窗口"。实际是：阈值收紧到真人 0% 时模板也 0%，
想捞到模板就先把真人成片捞进来（p25 那档真人段落点 31.8%）。换成只由 PR-HPPT 真人摘要估的二元表也一样
（p0.1 时模板 0~17%、真人 5~15%）。**没有达标的工作点，滑窗通道同样出厂即关闭。**
原因和解 4 节一样：窗口 bits/字 量的其实是"这段字像不像训练语料用词"，公开真人语料的语域和学生论文、
机器稿都不一样，困惑度先量的是语域差，不是平滑度。

## 6. 出厂了什么、关住了什么

出厂（随包、可核对）
- `assets/aigc/aigc-zh-weights.tsv`（351 KB，20,000 条 `w<TAB>n-gram<TAB>权重`，人能直接看）
- `assets/aigc/aigc-zh-freq.tsv`（547 KB，33,216 条字频派生量）
- `assets/aigc/aigc-model.tsv`（4.9 KB 清单：模型版本、训练数据与许可、切分方式、公共侧与真稿实测、
  滑窗阈值与阈值扫描、两条出厂门槛的判定结果、6 条黄金样本）
- `AigcNgramModel.java`：装载（FNV-1a 开放寻址表，20,000 + 33,216 条实测 63~101 ms，196,608 槽位）、
  句分、滑窗 bits/字、以及两条闸门 `calibrated()` / `windowCalibrated()`
- `tools/build-aigc-model.py`：`fetch / train / gate / export` 四步可重跑，门槛常量写在文件头
- `tests/AigcOfflineModelRegression.java`（34 条断言，已进 `tools/test-host.ps1`，缺文件或缺语料一律判失败）

关住（改一行代码就能开，但现在不许开）
- `AigcNgramModel.calibrated()` 必须**同时**满足：清单写 calibrated=true、清单里的真稿 AUC ≥ 0.85、
  真人误报 ≤ 2/千句。回归里专门验了"把清单里的旗子改成 true 但实测数还是 0.558 时仍然判不达标"。
- 闸门没开时 `AigcDetector` 一句都不问模型要分（`Result.modelSentences == 0`），
  `verdict()` 仍是原来那句"判据未标定…"，报告与界面继续不印 AIGC 百分比。
  这条判据和 `AigcScorer.calibrated()`（`v1-order-only`）是两道独立的闸，任何一道不开都不印数。
- 滑窗通道未达标时 `windowHit()` 恒为 false，一个窗口都不许算进可疑字数。
- 字数口径不双计：模型分数走的是原来的 `Sentence.score` → `Segment` → `flaggedChars` 那一条路，
  `CharLedger.close` 读的还是同一批 flagged 区间，交集只算一次。回归里验了"同一批可疑区间
  （含重叠）交两遍，60 字不变"。
- 语料不足报"样本不足"、不给比例那条（`MIN_DOCUMENT_CHARS`）一个字没动。

## 7. 还差什么

1. **装载那一行**。`AigcDetector.detect` 不会自己去开 assets，得有人调
   `AigcNgramModel.install(assets.open("aigc/aigc-zh-weights.tsv"), ...)`。
   `DuplicateEngine` / `EditorActivity` 不在这次允许改的清单里，所以这行没加 ——
   就算将来换了达标的模型，也得先补这行才会真的生效。
2. **想要 AUC ≥ 0.85，缺的是语料不是算法**：需要与真稿同域（学位论文 / 期刊正文长度）、
   机器侧是**现代大模型整篇生成**（不是"把真人稿润色一遍"）的中文标注语料，最好还带
   "要求规避 AI 风格"的机器档；真人侧要有多位作者的正文档。现成的公开集要么域不对（问答、检索短句），
   要么机器侧是润色档，要么要登录才拿得到（`QiYuan-tech/LLM-Detector` 那份是最接近的）。
3. **拉丁族（英文句）**：`AigcFamily.LATIN` 的句子明令不许用中文模型打分。英文语料已经下载
   （`Ateeqq`，MIT），要单独训一版才能补上。
4. **3.0.0 的语料那半边**：`tests/corpus/` 那份带来源与授权说明的清单、`AigcCalibrationSweep` 改读真标注、
   `AigcRegression` 加"缺语料即失败"的断言、标定表补"样本来源"列 —— 都在上一组那两台机器上，
   不在本轮可改的文件里。本轮的独立留出量法已经在回归里可复跑，可以直接接过去。
5. 已知失效场景（换模型也得防）：口语腔 / 书面腔的语域差被当成机写证据；润色痕迹被当成机写证据；
   规避风格的机器稿认不出；短文（不足 400 有效字符）本来就只给"样本不足"；中英混排句按中文族打分的那条
   折扣线（`MIXED_DISCOUNT = 1.00`）还没重定。

## 8. 怎么重跑

```
py tools/build-aigc-model.py fetch     # 取公开语料（默认代理 127.0.0.1:7897，--proxy "" 走直连）
py tools/build-aigc-model.py train     # 六组配置 + 选配置，落 artifacts/agent-aigc-offline/
py tools/build-aigc-model.py gate      # 真稿独立留出 + 滑窗落点 + 两条门槛判定，落 gate.json
py tools/build-aigc-model.py export    # 写 assets/aigc/ 三个文件（只写派生统计量）
pwsh tools/test-host.ps1               # 主机门禁：33 套全绿（含 AigcOfflineModelRegression 34 条）
```

Python 侧只需要 numpy + scikit-learn（`py -m pip install --proxy http://127.0.0.1:7897 scikit-learn`）；
Java 侧什么都不用加。原始语料留在仓库外，仓库里只有派生统计量。
