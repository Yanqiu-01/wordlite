# 抗改写召回实测台

`tools/test-host.ps1` 里的 `RewriteRobustnessRegression` 测一件事：**把一段真论文抄进稿子、再用某种口径改写过之后，
还有多少字会被标成重复**。0.7.3 的端到端召回实测台（`docs/retrieval-recall.md`）证明逐字复制那一头瓶颈在检索不在
匹配，这条断言只覆盖了逐字；改写那一头当时没有任何数字，只有"句级 Dice 0.55 应该扛得住一般改写"这种话。

## 口径

从 `tests/corpus/real-prose.txt`（真人写的论文正文，每行一段）里挑出有效字符不少于 120 的段，
**先用本应用自己的引文判据 `TextCorpus.citationLike()` 把参考文献条剔掉**（这一步是实测逼出来的，见下面"噪声"那一节），
剩下的段按奇偶分两拨：

- 偶数段进文献库，一段算一篇（`PAPER-0…PAPER-19`，共 20 篇 4567 字），它们同时也是被抄的段；
- 奇数段**永远不进库**，只当稿子里学生自己写的话，夹在被抄段之间。

稿子按"自己写一段 → 种入一段"交替拼出来，每个种入段在原稿上的区间和它应有的出处都记着。跑一遍真的
`TextCorpus.match()`，量三件事：

| 指标 | 算法 |
| --- | --- |
| 召回 | 种入段里被命中区间盖住的有效字符 / 这段的有效字符 |
| 归属 | 其中记在真正出处名下的字符 / 被标记的字符 |
| 噪声 | 那些没进库的段落被标成的字符数 |

命中区间互不重叠是 0.7.3 之后 `match()` 的结构性保证，实测台每条口径都重新数一遍相交对数，不为零直接抛
（`measure()` 里），因为一旦重叠，"盖住多少字"就会双算，整张表跟着作假。

噪声这一列是这台机器的关键。只报召回的实测台可以靠把阈值放松刷出任何好看的数字，所以每一行都必须同时给出
误报，而且实测台自己要先证明它看得见误报：`floors()` 里有一条断言把阈值压到 0.30 再测一遍，**必须**撞出误标来，
撞不出来就说明前面那一串零是瞎出来的。

## 十五种口径

全是确定性变换：同一份输入永远给同一份输出，不含随机数、不联网，所以能进闸门。

| 口径 | 做法 | 是不是真实降重写法 |
| --- | --- | --- |
| `verbatim` | 原样照抄 | 对照组 |
| `app-rewriter` | 本应用自己的离线降重 `LocalRewriter`，逐轮采纳第一条建议，采纳到没有为止 | 是，而且是产品自己那一头 |
| `synonym` | 24 组同义词/连接词整词替换（例如→比如、因此→所以、采用→使用…） | 是 |
| `clause-order` | 句内分句倒序（"因为 A，所以 B"→"所以 B，因为 A"） | 是 |
| `sentence-order` | 段内句序倒序 | 是 |
| `number-style` | 数目字写法互换：`12.5%` → `百分之十二点五` | 是，也是最常见的录入差异 |
| `drop-20pct` | 每五句丢一句 | 是 |
| `stacked` | 离线降重 + 分句倒序 + 丢两句 | 是 |
| `pruned` | 只留偶数位的分句：抄来的内容被抽稀成互不相邻的碎块 | 半真，专门打 18 字的指纹带 |
| `split-commas` | 句中每个逗号改成句号（拆句） | 是，降重手册上最便宜的一招 |
| `merge-pairs` | 相邻两句并成一句 | 是 |
| sub-char-10/25/50 | 每 10/4/2 个汉字换一个 | **不是**：逐字替换比任何真实同义替换都狠，用途是量容忍度曲线而不是模拟人 |
| local-edit-16/25 | 每 25/12 个汉字整块换掉 4/3 个连续汉字 | 半真：改动率和逐字替换可比，但空间分布是"几处疤"而不是"均匀铺开"，这才是 LLM 改写与大段誊抄的真实形状 |
| `spliced` | 上句的头接下句的尾，跨句拼接 | 是 |

## 实测（0.7.4，`SIMILAR_DICE = 0.50`）

20 段种入、85 句同领域负例，一轮 15 条口径：

| 口径 | 种入字数 | 标记字数 | 召回 | 归属 | 噪声 | 改动字数 |
| --- | --- | --- | --- | --- | --- | --- |
| verbatim | 4522 | 4513 | 99.8% | 100.0% | 0 | 0 |
| app-rewriter | 4518 | 4509 | 99.8% | 100.0% | 0 | 291 |
| synonym | 4517 | 4508 | 99.8% | 100.0% | 0 | 691 |
| clause-order | 4522 | 4515 | 99.8% | 100.0% | 0 | 3523 |
| sentence-order | 4522 | 4513 | 99.8% | 100.0% | 0 | 4336 |
| number-style | 4570 | 4570 | 100.0% | 100.0% | 0 | 2770 |
| drop-20pct | 3857 | 3848 | 99.8% | 100.0% | 0 | 1308 |
| stacked | 3856 | 3849 | 99.8% | 100.0% | 0 | 3965 |
| pruned | 3055 | 2987 | 97.8% | 100.0% | 0 | 3805 |
| split-commas | 4522 | 4493 | 99.4% | 98.8% | 0 | 197 |
| merge-pairs | 4523 | 4508 | 99.7% | 100.0% | 0 | 65 |
| sub-char-10 | 4522 | 4513 | 99.8% | 100.0% | 0 | 332 |
| sub-char-25 | 4522 | 1194 | 26.4% | 100.0% | 0 | 848 |
| sub-char-50 | 4522 | 76 | 1.7% | 100.0% | 0 | 1708 |
| local-edit-16 | 4522 | 4500 | 99.5% | 100.0% | 0 | 450 |
| local-edit-25 | 4522 | 4513 | 99.8% | 100.0% | 0 | 713 |
| spliced | 3040 | 3026 | 99.5% | 100.0% | 0 | 3328 |

四条立刻能用的结论：

1. **删和换序几乎不打不动这把尺子。** 丢两成句子、句序倒序、分句倒序、跨句拼接、并句，召回全在 97.8% 以上。
   原因是句级比的是三元组 Dice 与包含率：删掉的句子不在稿子里（不进分母），换序只打断跨在切点上的那两三枚三元组，
   而"抄来的半句整段嵌进改写过的长句"这一类由包含率那条路兜住。
2. **换字才是真正的悬崖。** 换掉一成汉字召回还是 99.8%，换掉两成掉到 26.4%，换掉一半只剩 1.7%。
   三元组重合度约等于 `(1-s)^3`，Dice 下限 0.50 折回替换率就是 `1 - ∛0.50 = 20.6%`——悬崖的位置和算式对得上，
   不是玄学。同理 0.55 那一档的容忍上限是 18.1%。
3. **数字写法不参与制造悬崖。** `number-style` 是唯一一条召回 100% 的改写口径，因为 `Fingerprints` 早把连着的
   数目字折成同一枚 token。0.55 时代这一条是 99.5%，降到 0.50 之后补齐。
4. **同样多的字，改动分布决定生死。** 换掉 450 字、集中在每句几处 4 字块里（local-edit-16），召回 99.5%；
   换掉同样量级的字、均匀铺在整段上（介于 sub-char-10 与 sub-char-25 之间），召回从 99.8% 一路掉向 26.4%。
   原因是 n-gram 只数连续重合：整块替换只在疤周围毁掉 块长 + n - 1 枚三元组，长段原文照抄的部分整段活着；
   均匀替换让每一枚三元组都带着 1-s 的概率被打散。**结论对产品的意义很大：真实降重（局部换词、调序、并句、删句）
   打不动这把尺子，能打动它的只有把全文每个词都换一遍那种改写，而那已经不是"抄"而是照着重写。**
5. **本应用自己的离线降重太温和。** 20 段一共只改动 291 字（每段约 15 字，全文的 6%），因为规则刻意让数字、
   单位、型号、术语整个活着——那是对的（改了术语就不是降重是改错），但也意味着降重功能实际推动的改写量很小，
   `app-rewriter` 这一行离 `verbatim` 几乎没有距离。这条差距记在 ROADMAP，不在匹配这一头解决。

## 阈值扫描（`-Drrs=1`）

同一份稿子、同一个库，只动 `diceFloor`，召回与噪声一起报：

| dice | 噪声 | sub-char-25 | pruned | split-commas | spliced |
| --- | --- | --- | --- | --- | --- |
| 0.55 | 0 | 19.2% | 96.2% | 98.1% | 99.3% |
| 0.50 | 0 | 26.4% | 97.8% | 98.1% | 99.5% |
| 0.45 | 0 | 31.3% | 99.4% | 97.1% | 99.7% |
| 0.40 | 0 | 46.1% | 99.4% | 97.1% | 99.7% |
| 0.35 | **399** | 66.5% | 99.4% | 97.1% | 99.7% |

包含率那一列（0.90/0.80/0.70）在这台机器上逐位相同，和标定台当年的观察一致：能配上的句子长短本来就接近。

**0.55 降到 0.50 的理由与边界。** 当年留 0.55 的话是"0.50 与 0.55 实测逐位相同，多留一档余量给真实文库"，
那句话在原文与常规改写的样本上成立，在逐字替换的样本上不成立：同一批 20 段、同一批 85 句负例，
两成替换那一档差 7.2 个点，分句抽稀差 1.6 个点，而两边误报都还是零。标定台在现行代码上重跑过，
`ENGINE CURRENT` 与 `dice=0.50` 那一行逐位相同（召回 99.5%、误报 471 字、`dupChars=3634`），
说明这一改在原六种写法上一笔未动，只在重写口径上多认回字。

**为什么停在 0.50 而不去 0.45**：0.45 还能再多认回约 5 个点，但下面那张分布表显示这批负例能摸到的最高
Dice 是 0.358，0.50 头顶还有 0.14 空档，0.45 只剩 0.09；文库上了几千篇几万篇规模之后偶发撞车要吃的正是这一档。
哪天真实文库规模够大、负例天花板仍压在 0.36 以下，再往 0.45 走，走之前先把这张表重跑。

## 漏掉的字卡在哪一层（`-Drrroc=1`）

把阈值临时压到近零，让每个句子都把"库里最像的那一条"报出来，漏检的原因就分得开了：分值堆在 0.45~0.55 之间
是阈值卡住的，分值正好是 0 的是**压根没问到候选**。

`sub-char-25` 的 83 句正例：`=0` 零句、`(0,0.3]` 10 句、`(0.3,0.4]` 37 句、`(0.4,0.45]` 12 句、
`(0.45,0.5]` 3 句、`(0.5,0.55]` 6 句、`>0.55` 15 句。**阈值那一头最多只能捞回 9 句**，剩下 45 句压在 0.45 以下，
不是调阈值能解决的——那需要词序无关的特征（词集/语义），不是 n-gram 家族能做到的事。

按句长分桶再看一次，顺便否掉了一个顺手就能想到的方案：

| 句长 | 负例句 | 负例最高 Dice |
| --- | --- | --- |
| <20 | 1 | 0.158 |
| 20-35 | 8 | 0.179 |
| 35-50 | 21 | 0.152 |
| 50-80 | 40 | **0.358** |
| ≥80 | 15 | 0.162 |

"长句证据多、所以长句可以把下限放松"这个说法在这批样本上不成立：负例能摸到的最高分恰恰出现在 50-80 字的
长句桶里，短句桶反而 lowest。**长度加权的方向和直觉相反，所以这条方案不做。**

归属那一头有两个数字值得记：`sub-char-25` 换掉两成字之后，最佳候选**指对正确出处**的字符仍然是 4522/4522——
排序全对，只是被阈值挡在门外，这进一步说明要动的是判定线不是候选生成。而 `split-commas` 只有 1705/3937，
196 个碎片里 93 个连候选都没问到：包含率那条路的可达区间是长短比 1.6 到 3.0（`dice >= 0.5` 这一条自己把
比值上限卡在 3.0），拆出来的 16 字碎片对 54 字原句是 3.4 倍，结构上就进不了那条路。

## 一条被顺手挖出来的口径错误：抄得更多，报得更少

给拆句放宽包含率通道（长短比 3.0 → 4.3）之后，`split-commas` 从 98.1% **掉到** 92.8%。放宽一条判定线反而少认字，
只可能是判据之间互相咬。逐条打出来看是这里：**指纹带只补句级命中没盖住的字符，而"补不出最短可报告长度就丢掉"
这一刀是逐块量的**。一条 40 字的连续复制，中间被一句句级命中咬掉 8 个字，剩下两块各 16 字，两块都够不到
`MIN_MATCH = 18` → 全丢。于是句级命中越是先咬一口，带子能报出来的越少。

改成按"这条带子还剩下多少字"判：总长够 `MIN_MATCH` 就把剩下的每块都留下，归属与分子照旧走同一次并集。
理由不是"多报一点没关系"，而是证据本来就是这条带子——winnowing 保证的连续重合，被句级命中咬掉一段
并不会把剩下的字变成巧合。改完之后 `split-commas` 99.4%、`pruned` 不变、噪声仍为 0，标定台那一头
`ENGINE CURRENT` 逐位不动（召回 99.5%、误报 471 字、`dupChars=3634`、命中 60 条），PAIR / CROSS 误报仍是 0.0%。

那条被回滚的放宽实验留在这一段里，因为它是这台实测台唯一一次自己抓到自己：没有它，这个分块错误还会在
判据里躺很久，而它平时表现成的样子是"某些拆过句的段落就是不红"。

## 嵌入改写：抄进去一句 22 字，报出来整句 90 字全红

上面那次放宽还暴露了另一件事，而这件事这台机器以前**看不见**：包含率命中记的区间是**整个片段**，
不是实际共享的那一段。于是单独加一档 `embedding`——把库里某篇的一句短句整块嵌进一句学生自己写的长句里：

| 量 | 实测 |
| --- | --- |
| 嵌进去的那段 | 778 字，标了 716 字 = **92.0%**（该认的认回来了） |
| 它外面的自写文字 | 1578 字，被连带标了 688 字 = **43.6%** |

也就是说抄一句进去，句子外面自写的部分有将近一半跟着一起红。这一档之前没有任何一台机器量过它：
标定台的 `MARGIN` 只量 Dice 一条路，`docs/detection-calibration.md` 的"还没解决的"里那条
"长短悬殊的嵌入改写没进这批样本"说的就是它。

这个数字现在以**天花板**的形式钉在闸门里（平均每句连带标红不许超过 45 字），不是达标线：等包含率的命中
落到实际共享区间（`docs/ROADMAP.md` 1.1.1），它应该一路掉到个位数。顺序不能反——先把包含率通道放宽，
多报的那一头只会更大，这正是上面那次回滚量出来的代价（多报 3 倍，26 字的复制报成 85 字）。

## 落点裁到实际共享那一段：每句 41 字掉到 0 字，代价是四段拼接少认 4 字

1.1.1 改的就是这条落点。判据一个字没动，改的是命中记在哪一段：`SharedBlocks` 在折叠后的比较键上做二分公共块长度 + 滚动哈希求最长公共块，找到之后往两端各自扩到极大，再在剩下的左右区间里找下一段，一个片段最多 16 段；每段开销 `O((n+m)·log min(n,m))`，不建 n×m 的 DP 表，临时表逐句复用。两端再剥掉标点与符号才折回原文偏移——学生自己敲的那枚逗号常常正好对上文库那句里两个分句之间的逗号，字符串层面确实相同，可 `validCount` 认它为一个有效字符，不剥就是一枚凭空多出来的红。

| 量 | 裁之前 | 裁之后 |
| --- | --- | --- |
| 嵌进去的那段 | 723/778 = 92.9% | 720/778 = **92.5%** |
| 它外面的自写文字 | 681/1578 = 43.2%（每句 40 字） | **0/1578**（每句 0 字） |

（这两行是夹具窗口修正之后的数：`phraseStart` 原来多算一个字符，17 句逐句 `indexOf` 复核每句都差 1。上面那行 92.0% 是旧窗口口径下量的，裁前裁后必须用同一个窗口比。）

多报从 681 字掉到 0 字，只裁回来 3 个字。代价在哪：

- 丢的 3 字来自 1 句（probe 16，PAPER-19）。抄进去那句以序号 `1）` 开头，而入库那侧 `skipPrefix()` 会把序号前缀剥掉，两边的折叠串在这 3 个单位上本来就不相同——共享块不可能诚实地从更早的位置开始。其余认回来的句子，命中区间与被抄区间逐字相等（`[12,40)`、`[277,337)`、`[393,470)`、`[519,618)`）。
- `merge-pairs` 4508 → 4504（99.7% → 99.6%）、`spliced` 3026 → 3024。原因是同一个片段里有两句都过了线（同篇相邻两句、或两篇各一句）时，只裁进赢的那一句会把另一句连证据一起藏掉。于是加了守卫：**只有一个片段恰好只跟一个候选对得上时才裁**，多候选的片段整段报——抄两段只报一段比多报更糟。这条守卫同时把 `TextCorpusRegression.merging()` 顶了回来，那条钉的是「合并区间要盖住第一个到最后一个重复字符」，它不是可以改写的措辞。
- 17 句里另有 3 句（54 个有效字符）裁之前裁之后都没有命中，与裁剪无关：`LENGTH_BOUND_FLOOR = 0.5` 把这条通道的长短比封顶在约 3.0 倍，那三句的 gram 比是 6.6 / 4.9 / 3.5。那是 1.1.2 的活。

标定台 `ENGINE CURRENT` 在改动前后逐位不动（`recall=99.5% fpChars=471 dupChars=3634 hits=60 boilerplateShare=17%`）：这份真人语料里没有嵌入几何的命中，所以这次改动在真实论文上的第一层影响是「不变」，它搬动的只有嵌入与拼接这两种形状。闸门里的天花板从每句 45 字收到 4 字（实测 0）。

还没跟着改的：`hit.score` 仍是那一对片段的加权 Dice，不按裁后区间重算，所以一条窄命中的分值说的可能还是整个片段的相似度；`MIN_SHARED_BLOCK = 5` 与 `MAX_SHARED_BLOCKS = 16` 只在宿主用例上定过，没在真文档标定台上扫过。
## 噪声那一节：参考文献条是自己人打自己人

第一版实测台没有 `citationLike` 过滤，噪声一列全是 1149 字，逐条打出来看全是这种东西：

```
NOISE chars=24 score=0.667 source=PAPER-24 :: 2024, 39(10): 13471-13486.
NOISE chars=20 score=1.000 source=PAPER-1  :: Transient Liquid Phase
NOISE chars=20 score=0.772 source=PAPER-25 :: 2020, 10(7): 934.
NOISE chars=148 score=1.000 source=PAPER-36 :: Novel Transient Liquid Phase Bonding through C
```

参考文献条互相判重是**真实存在**的行为：同一本刊名、同一个 `et al.`、同一副英文题名在文档里出现两次，
逐字重合当然高。它算不算冤枉要看场景——同一份文献表里同一条列两遍是真重复，而"稿子里的参考文献表"本来就该由
`TextCorpus.structure()` 的参考文献区识别整体退出比对。实测台把正文和参考文献混在一起测，只会把正文那一列的噪声
数字弄脏，所以现在用应用自己的 `citationLike()` 先把 38 行进库位、若干行负例位剔掉。这条行为差异记在这里，
是为了防止下一次有人拿参考文献的分数当误报率。

## 已知不足

- `sub-char-*` 是逐字替换，不是任何真实改写工具的输出；它能定容忍度的上限和悬崖位置，不能当成"某某降重软件
  改过的稿子我们能认回多少"。真实第三方改写工具的量级没有测过，因为没有可复现的第三方工具输出可喂。
- 文库是**同一篇论文的 20 段**，负例是同一篇论文的 65 句正文。同领域同源，术语全撞车，这是诚实的负例，
  但它代表不了几千篇文库下的偶发撞车；天花板数字（0.358）只在这一批样本上成立。
- 种入粒度是段，命中粒度是句，所以"半句抄、半句自己写"这种句内混合没有单独一档口径；`pruned`/`spliced`
  是它粗糙的替身。

- AIGC 判定与这台机器完全没有关系，别拿上面任何一张表当 AIGC 的标定物（那边仍然缺带标注的人写/机写语料）。

## 1.1.2：包含率通道拿到自己的地板

## 1.1.4：第三条判据（字符袋）——`sub-char-25` 26.4% → 53.8%，噪声仍为 0

判"像不像"的从来只有两条：三元组 Dice（`SIMILAR_DICE = 0.50`）和长短悬殊时的三元组包含率
（`SIMILAR_CONTAINMENT = 0.90`）。两条数的都是**顺序相关的 n-gram**，所以逐字替换按三次方的速度打掉判据：
换掉 25% 的汉字，三元组 Dice ≈ `(1-0.25)^3 = 0.42`，够不到 0.50，那一批字（4522 字只报出来 1194 字）
是结构上查不出来，跟阈值怎么扫无关（`-Drrroc` 那一节已经把话堵死：83 句正例在阈值那一头最多捞回 9 句）。

第三条判据数顺序无关的**字符袋 Dice** `2|A∩B|/(|A|+|B|)`（`TextCorpus.SIMILAR_BAG_DICE = 0.72`）：同一档它只掉到
`2(1-s)/(2-s) = 0.857`。三条判据是 OR，一条也不替换。落点与包含率那条共用 `clipToSharedBlocks`，
`hit.score` 不抬，理由写在下面。

### 这一版没修的那一半：候选还得先被三元组捞起来

`bestMatch` 的候选来自三元组倒排，还要过 `shared >= MIN_SHARED_GRAMS(3)`。袋口径改的是**打分**，没改**取候选**
那一步：改写重到连三枚首尾相接的三元组都不剩的句子根本进不了这个循环，袋 Dice 再高也没人生效。这才是
`sub-char-50` 只有 7.6% 的原因——不是袋口径不行（句级过线率 14.5%），是那些句子没进候选。补法是字符袋倒排 +
PPJoin 式前缀过滤，排在 `docs/ROADMAP.md` 第二轮。

### 落点与分值：这一档不许虚报

- 落点走 `clipToSharedBlocks`，只报两边实际共享的那几段，`passed == 1` 才裁（与 1.1.1 同一条规矩）。嵌入档
  带外连带标红仍是 0 字，闸门里的多报天花板（每句 ≤ 4 字）不动。夹具实测：67 字的改写句红 41 字，剩下 26 字
  是自己写的与改写掉的；被换掉的词（车位管制 / 孤立地 / 权衡 / 城区路网 / 管控）一个都没整块红。
- `hit.score` 不抬：这一档报出去的分值仍是字面三元组 Dice（夹具那一例 0.47），改写越重报出的分越低。分值不许
  超过字面证据——用户读到的必须是"这两句有这么多字一模一样"，不是"这两句很像"。
- 代价一：三元组阈值单独能挣的那截变薄。`sub-char-25` 上 0.50 相对 0.55 的增益从 7.2 个点
  （19.2% → 26.4%）缩到 3.7 个点（50.2% → 53.8%），`floors()` 那条反证的地板跟着 6 → 3；`sub-char-25`
  的召回地板 26 → 50，哪天这条通道被改窄，这条先红。
- 代价二：真文档标定台有了动静但不大——`ENGINE CURRENT` recall 99.5% → 99.6%、`dupChars` 3634 → 3636、
  命中 60 → 58 条、`fpChars` 471 不动、boilerplateShare 17% 不动，`PAIR dice=0.50` 同源误报仍 0.0%。
  这份真人语料的正例六种写法全是顺序相关的，没有逐字替换这一族，所以它在真实论文上的第一层影响仍然是
  "几乎不动"，真正的靶子是大模型改写与 `sub-char-25` 那一族。
- 台账：`TextCorpusRegression` 183 → 200（新增 `bagChannel()`：度量性质、A/B 证明那条命中确实归这条通道、
  落点只红公共段、分值仍是字面 Dice、同领域另一件事不撞车）；`RewriteRobustnessRegression` 69 → 81

## 1.1.5：句长门那一档量过了，停在 12（新增 `chopped` 口径当复现器）

计划里写的是 D4：`MIN_SENTENCE_CHARS` 12 → 10，同时把短句桶的共享三元组地板 3 → 5，理由是"拆句抄出来的
碎片常在十字上下，12 那道门连问都不问"。这一档在这台实测台上量不出来——不是因为没试，而是因为**短的逐字
碎片根本不由句长门管**。

先补一档能看见它的口径。`chopped`：把抄来的段落每十个字补一个逗号，重新断句成十字一段的碎片（改动字数
4760，比 `clause-order` 还狠）。然后 `-Drrd4=1` 逐档扫句长门，同一份夹具（夹具与文库怎么造句子用的是常量
12，引擎里那一档是活值，所以四行同底可比）：

| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| **12** | 99.8% | 99.5% | 99.5% | 99.0% | 53.8% | 720/778 | 0 | 0 |
| 11 | 99.8% | 99.5% | 99.5% | 99.0% | 53.8% | 720/778 | 0 | 0 |
| 10 | 99.8% | 99.5% | 99.5% | 99.0% | 53.8% | 720/778 | 0 | 0 |
| 9 | 99.8% | 99.5% | 99.5% | 99.0% | 53.8% | 720/778 | 0 | 0 |

短句桶共享三元组地板那一维（3 与 5）在同一批口径上也是逐位相同，扫完直接删掉了这条通道，没留成一个没人读的旋钮。

为什么放开门一点用没有：`chopped` 在门是 12 的时候就已经 99.5%。接住它的是**指纹带**那一层——
`Fingerprints.tokens()` 跳标点，所以补进去的逗号在 token 流里根本不存在，一段两百多字的段落被切成二十来个十字

多少可丢的：`split-commas`（拆到十几个字一句）本来就顶在 99.5%。

结论：**这一档不动**，12 保持。要推翻这条结论得先拿出一档能看出差别的口径（比如"十字上下、且每片都改写掉
几个字"的碎片——那已经不是一句能造出来的话，得从真稿子里取）。`TextCorpus.MIN_SENTENCE_CHARS` 的注释里记着
这条，`TextCorpusRegression.shortFragments()` 钉住"十字一刀的抄写至少认回 95%"，`floors()` 里
`recall(scores, "chopped", 99d)` 钉住这一档不掉。哪天再有人提"把句长门放开"，先跑 `-Drrd4=1`。

台账：`RewriteRobustnessRegression` 81 → 84（新增 `chopped` 口径、`-Drrd4` 扫描台、噪声与归属跟着全表跑）；
`TextCorpusRegression` 200 → 203。产品判据一个字没改——这一版的交付物是一次实测与一条被否掉的计划。

## 1.1.6：取候选这一步脱离三元组；袋口径的分值不再打零分

1.1.4 那一节末尾写着"没修的那一半"：`bestMatch` 的候选只来自三元组倒排，还要过 `shared >= MIN_SHARED_GRAMS(3)`，
所以改写重到不剩三枚首尾相接三元组的句子**根本进不了打分**，袋 Dice 再高也没人生效。这一版把那一步补上：
给每个条目建字符袋倒排（字 -> 装过这个字的条目号），片段拿自己最稀的几枚字去查，凡是共享其一的条目都进
精算。种子只决定"去验证谁"，判据一个字节没动——过线仍然是精确袋 Dice >= 0.72，所以种子取得松紧不会让任何
一句话改变判定，只会让它被多验或漏验。开销三档封顶：每片段 4 枚种子、单枚 posting 扫 256 条、每片段最多精算
64 个候选；df 超过 64 的字整条不进索引（那类字谁都装，当种子只是白扫）。

### 实测：这两份语料上一个字符的召回都没多

| 口径 | 1.1.5 | 1.1.6 |
| --- | --- | --- |
| 全部 18 档（含 `sub-char-50`） | 99.8 / 99.5 / 53.8 / 7.6 … | **逐位相同** |
| 噪声（18 档） | 0 | 0 |
| 标定台 `ENGINE CURRENT` | recall 99.6% fpChars 471 dupChars 3636 hits 58 | **逐位相同** |

`sub-char-50` 为什么不动，量清楚了：这一档的替换是**均匀**的，换掉一半汉字之后两句共享的字数就剩一半，
袋 Dice 自己就掉到 0.5 上下，本来就够不到 0.72；而句级过线那 14.5% 的句子，多半还留着三枚以上共享三元组，
1.1.4 那条通道已经把它们接住了。两个集合基本是同一批——所以这台机器上买不到增量。

那这一版买的是什么：**能力缺口确实存在，而且现在能证明它被补上了。** 夹具做不出这种句子（`sub-char-*` 是均匀
替换，不是任何一种真实改写），所以用一条机制断言钉住（`TextCorpusRegression.bagChannel()`，203 → 206）：
把整句**倒过来写**，字符袋一个字不差（袋 Dice 1.0），字面三元组一枚不剩（Dice 实测 **0.0**）——改之前
`match()` 一条都不报，现在报一条，且把地板抬到 1 以上那条路整条空转（精算数归零）。这不是为了抓"倒着抄"，
是为了钉住"取候选不再只认三元组"。真实大模型改写正是这个形状的温和版：术语（最稀的那几枚字）原样留着、
句子结构全换——那批句子在均匀替换的夹具里造不出来。

开销实测（9242 字稿子对 194 句文库，台式 JVM，`pwsh tools/bag-rescue-probe.ps1`）：袋口径这一路多精算
**1847** 个候选；同一台 JVM 各跑四轮，关掉袋口径 19-24ms、开着 12-22ms，两轮互相穿过，差别落在跑批噪声里
——结论只敢写到"看不出可分辨的增量，上限由那三档封顶保证"。

### 但这一版真正修掉的是误报：袋口径只管大字母表上的文本

探针顺手把同一篇论文按单双行劈成稿子与文库裸跑了一遍（`SAME-DOC` 那一行）。袋口径净新增 **1424 字 / 15 段**，
样例逐条看过去全是参考文献条目：

```
+139 字 score=0.69：HOU F, SUN Z, SU M, et al. Review of Die…
 +78 字 score=0.72：Recent Progress in Transient Liquid Phas…
 +25 字 score=0.59：电源学报, 2024, 22(3): 62-71.
 +70 字 score=0.59：YOON J W. Cu-Sn and Ni-Sn Transient Liqu…
```

这是一条被漏掉的性质：**袋是"出现过哪些字"的集合，所以它的误报率由可用字有多少决定**。汉字可用字上千，
两句不相关的中文撞不到七成五；拉丁字母折成小写只有二十六个加十个数字，同一个子领域的两个英文题名、
两条参考文献，字符袋天然互相包含。于是拿同一份真人语料（`tests/corpus/real-prose.txt`）跨条目两两配对，
按拉丁占比分桶量（`pwsh tools/bag-false-positive-probe.ps1`，125 条、880 个不同字）：

| 过线配对（袋 Dice >= 0.72） | 对数 | 最高袋 Dice | 共享稀字(df<=8)上限 |
| --- | --- | --- | --- |
| 两边都是中文（拉丁占比 < 0.15） | **0** | — | — |
| 两边拉丁占比都 < 0.5 | **0** | — | — |
| 拉丁占比 >= 0.5 | **406** | **1.000** | 0 个（df<=16 时 1 个） |

分桶明细 `<0.05 / 0.05-0.15 / 0.15-0.3 / 0.3-0.5 / >=0.5 = 0 / 0 / 0 / 0 / 406`，过线配对里**最靠近门的那一对
是 0.743**。结论不是"阈值再抬高点"能救的：拉丁袋的 0.72 就是"两句毫无关系也过线"，只能不问。

门借 `AigcFamily.LATIN_RATIO`（0.50，"这一段算拉丁族"那档，0.5.4 起就在用）：两边都不是拉丁族才让袋口径参与
判定，落点在 `TextCorpus.BAG_LATIN_CEILING`。**为什么不放在混排那一档（0.15）**——放在 0.15 会把含化学式与
英文术语的中文句子一起请出去：

| 门放在 | sub-char-25 召回 | sub-char-50 召回 | 过线负例（拉丁占比 < 门） |
| --- | --- | --- | --- |
| 不设（1.1.5 的行为） | 53.8% | 7.6% | 406 对 |
| 0.15 | **51.6%** | **2.5%** | 0 对 |
| **0.50（这一版）** | 53.8% | 7.6% | 0 对 |

0.15 到 0.5 这一桶里一个负例都没有，所以那一档只是白白砍掉中文召回。门放下之后：18 档口径与标定台
`ENGINE CURRENT` 逐位回到 1.1.5 的数字；裸跑那一遍的袋口径净新增从 1424 字降到 **86 字 / 4 段**（剩下四条是
夹在参考文献条目里的中文期刊名与年份——拉丁占比为零，门管不着它们，管它们的是结构性文本排除）；走产品口径
（`TextCorpus.structure` 排除参考文献表与标题，与 `DuplicateEngine` 传的第三个参数逐字相同）净新增 **0 字**。

代价写在常量上，也写在这里：英文整句改写（换了词、剩下同一批字母）这一版起不由袋口径接住。字符袋在
拉丁字母上给不出安全阈值，要接住它得换词级袋（词干/引形），那是另一条判据，排在 `docs/ROADMAP.md`；
逐字抄的英文照旧由三元组 Dice 与包含率那两条管。

### 顺带修掉一处会吓到用户的分值

袋口径 1.1.4 定的是"`hit.score` 不抬、仍打字面三元组 Dice"。那句在袋口径只可能带三枚以上共享三元组时还讲得通；
候选一旦由字符袋倒排补进来，字面三元组可以是零，于是证据表上出现**"相似度 0.0%"配一段红字**——这正是用户
会报成 bug 的那类东西（1.1.3 那次报 0.00% 就是同一形状）。现在袋口径两条路统一：
`score = max(字面 Dice, 袋 Dice x 0.8)`。0.8 这个系数沿用包含率那条通道（`containment * 0.8f`），不是新发明的。
相似率的分子是字符数，与这个分值无关，改的只是证据表那一格；`TextCorpusRegression` 里那条"不许拿袋口径的分
顶上去"的断言跟着改成新口径，其余分值断言逐条重扫通过。

台账：`TextCorpusRegression` 203 → 206；`RewriteRobustnessRegression` 84 条逐位不动（18 档召回、噪声、归属、
嵌入档全同）；标定台逐位不动。

## 降重器只换掉命中区里三成的字：逐段覆盖率与三把尺

`RewriteRateRegression` 只报端到端那一个数（靶子 3.14% → 2.42%，516 字 → 398 字），它不回答"为什么只降这么多"。
这一轮把那一遍拆开量：同一个靶子、同一条判据、同一套 Limits，逐段数"命中区里有多少字能动、动得了的里面有多少
在替换表里有候选、表里有候选的点为什么没落地"。实测台是 `tests/RewriteCoverageAudit.java`，只吃本地语料，不在
`tools/test-host.ps1` 的必跑清单里：

```
pwsh -NoProfile -File tools/run-suites-private.ps1 -Tree <私有树> -OutDir <私有目录> -Suite RewriteCoverageAudit
```

口径与 `RewriteRateRegression` 逐字相同（同一个库、同一份插句靶子、depth 8 / candidates 8 / rounds 10 /
verifications 240，实 used 175 次），所以这里的 516 → 398 与那条回归报的是同一个数。词表不在实测台里复刻第二份：
出现点读 `LocalRewriter.lexicalTable()`，规则点数由 `LocalRewriter` 自己在改写时扫（`startTally()` 只在实测时装，
产品路径上那个计数器一直是 null，改写结果一字不差：`LocalRewriteRegression` 431 条、`RewriteRateRegression` 67 条

### 覆盖率为什么上不去：八成缺口是术语

实测台把"表里根本没有候选的槽位"逐字打出来（表 2b / 表 2c），并按一张固定术语字根表拆一刀（字根一律取两个字
以上，免得用一个单字把普通词位也算成术语、把上限说虚高）：改完仍在命中的 10 段里 48 个去重槽位，
**含术语字根 34 个 / 202 字，不含术语字根只有 14 个 / 49 字**（字数按整槽计，偏大）。含字根的那批就是
切削力 / 温度场 / 应变场 / 变形区 / 测力仪 / 乳化液 / 机理 / 规律 / 形貌 / 裂纹——按下面的安全规则不许动。
不含字根的开放词位全清单也打在同一张表里：内部发挥良好、形成、影响、受限、能凸显出、形成过程、归因、结果来看、
通过、分析、能探讨、加精细、续将进行该方面、研究。

### 意义安全规则（这个功能是照着这张清单建的）

不许换：数字与单位（含 50% ↔ 半数 这类）、程度词（显著 / 轻微 / 大幅 这一档）、否定、比较方向（高于 ↔ 低于）、
因果强度（导致 / 引起 / 造成 之间），以及任何会改掉"这段话声称了什么"的搭配。不许做的动作：制造断词机会、
插入零宽或不可见字符、用标点或空格凑字、删掉实词让区间变短。

按这张清单否决掉的候选，都不进表；写在这里是为了下一个人别把它们当成"召回不够"补回来：

| 候选 | 否决理由 |
| --- | --- |
| 导致 → 引起 | 跨因果强度：导致是强归因，引起可以是伴随 |
| 显著 → 明显 | 跨程度：显著带"统计学上显著"的读法 |
| 高于 → 低于 | 直接翻比较方向 |
| 试验 → 实验 | 这篇正文里切削试验（机床上的试验）与实验（实验室）是两回事 |
| 机理 → 机制 | 材料去除机理是术语，机制是另一个词 |
| 规律 → 规则 | 温度相关规律不是规则 |
| 结果 → 结论 | 结论是论文的主张，结果是测出来的东西 |
| 影响 → 作用 | 换完所指变了 |
| 形成 → 产生 | 形成带"逐步成形"的体貌，产生不带 |
| 采集 → 收集 | 采集频率是测量术语 |
| 结合 → 依据 | 句子从"参照"变成"根据" |
| 通过 → 借助 | "通过对……的分析"里通过是介词，借助接不上 |
| 分析 → 剖析 | 词义不翻，但"……的分析"是名词位，换完不通顺；拿不准就不加 |

也要照实写：表里**已经有**两对与这张清单不合拍——`显著 ↔ 明显`、`导致 ↔ 引起`（另有 `高于 → 大于`，
两边都是"大于"，方向没变，只是把比较记号换成数学记号，勉强站得住）。这轮没动它们：动它们要单独一条改动，
并且要把 `RewriteRobustnessRegression` 的 18 档与 `DetectionFloor`、`AbstractLayerRegression` 一起重量。

### 这一轮加了三对，每对都由一个真实幸存词位撑腰

| 新表条目 | 证据词位（改完仍在命中里、且表里没候选） | 禁字与理由 |
| --- | --- | --- |
| 出现 → 产生 | 工件表面出现裂纹 | 禁后字：在 / 时 / 频 / 标点。出现在、出现时间、出现频次，以及句末不及物用法——"产生"要接宾语，也免得"什么时候被发现"变成"什么时候生成" |
| 起到 → 发挥 | 内部起到良好的冷却作用 | 无 |
| 相同 → 同样 | 相同切削参数 | 禁前字：全 / 不 / 致 / 略 / 本 / 均（完全相同、不相同、均相同换完要么不通要么改掉范围）；禁后字：点 / 处 / 字母数字（相同点、相同 SAC305） |

加完：覆盖率 22.0% → 23.6%，出现点 41 → 44，落地 38 → 41，改掉的字数 68 → 73（占可动字 17.8% → 19.1%）。
**整篇读数一字未动：3.14% → 2.42%、516 → 398 字、175 次整篇验证。**

### 三把尺：多出来的替换是真距离

后两把在实测台里自己算（清洗 → 字符二元组 → `log((1+N)/(1+df))` 加权 → 余弦；ROUGE-L 是按字的 LCS 的 F1），
背景就是被抄那 11 句；它们不引用 `TextCorpus` 的任何常量、切句、袋或三元组，就是为了能回答"是不是只学会了
躲自家那三条阈值"。

| 尺（11 个命中段的均值） | 加词前 | 加词后 |
| --- | --- | --- |
| 自家判据命中字数 | 516 → 398（降 22.9%） | 516 → 398（降 22.9%） |
| 二元组 TF-IDF 余弦（对整篇来源） | 0.3460 → 0.3054（降 11.7%） | 0.3460 → 0.3035（降 12.3%） |
| 同上，对最像那一句 | 1.0000 → 0.8581（降 14.2%） | 1.0000 → 0.8461（降 15.4%） |
| ROUGE-L（对最像那一句） | 1.0000 → 0.8751（降 12.5%） | 1.0000 → 0.8645（降 13.5%） |

方向要看清：**外尺在动，自家读数钉在 398 不动。**这不是"只学会了躲自己的阈值"（那个形状是自家读数掉、外尺平），
而是自家判据在这一段区间里对真实距离不敏感。顺带一句：实测台末尾那句判定用 10 个百分点做分界，加词前判据比
ROUGE-L 多降 10.4 个百分点，加词后 9.4 个百分点，那句话正好从"有相当一部分是躲自家判据"翻到"同步"——
这条线是我随手定的，别把它的翻面当结论，能当结论的是上面三个数一起看。

### 再加两对会怎样（只在私有树里试过，没进版本库）

幸存词位里还剩 研究（进一步研究 / 该方面的研究）与 分析。在私有树里把它们加成 `研究 → 探究`、`分析 → 剖析`
再跑同一台实测台：覆盖率 23.6% → 25.1%，出现点 44 → 47，ROUGE-L 降幅 13.5% → 14.3%，整篇验证 175 → 182 次，
第 11 段 6 个可落点里只有 2 个被采纳（另外 4 个"没让整篇命中字数变小"，被闭环回退了——这条规则保留），
**整篇读数仍然一字未动，还是 516 → 398。**

代价是两处真值断言各红一处：`tests/LocalRewriteRegression.java:213` 的
`checkNoCandidate("无规则命中", "本文研究了工艺参数对接头质量的影响。")`，以及
`tests/RewriteRateRegression.java:340` 用同一句话做的"改不动的那一段：数字没变、采纳数为 0"。两处都把这句
普通论文句钉成"没有任何规则适用"。要不要换掉这两处的样例，是"研究算不算可换词"这个决定本身，不该由扩表顺手
带过去，所以这轮没做。

### 结论：这 398 字，安全替换推不动

11 个命中段里 4 段（32 / 56 / 54 / 37 字那种）改完仍是满额命中。它们的可动字绝大多数落在术语上，而
`ParaphraseRecallAudit` 量过这台的门限：同义替换 20% 仍被认（100.9%），35% 才开始丢（52.3%）。安全替换能把
覆盖率推到 23.6%，剩下的头是切削力 / 温度场 / 应变场 / 变形区 / 测力仪 / 乳化液 / 机理 / 规律这一批不许动的词。
所以"改完还有 398 字在命中里"不是降重器少干了活：这段材料本来七成就在术语上，要把它推到判据认不出，只能动
术语或者改掉主张，那两件事都比"把这段标成重复"更糟。想让这个数真的动，得先动判据在那一段区间的敏感度，
或者接受上面那两处真值断言换样例——不在这轮的范围里。
