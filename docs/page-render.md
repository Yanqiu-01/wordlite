# 手机里的 FlareSolverr：WebView 渲染取正文

本机那一轮（`docs/endpoints-access.md` 第二节）拿 Docker 里的 FlareSolverr 把万方详情页渲染成 3,331 汉字，
其中 1,500 上下是网站自己从整篇里摘的「全文精要」。那是笔记本上的东西：Docker 装不进 APK。
用户手机上有 WebView，后台加载一页、`onPageFinished` 之后取 `document.body.innerText`，
就是装在用户手机里的同一台机器。这一页写清它替掉哪一步、参数为什么是那个数、失败分几种、以及真机量到的读数。

## 两个类的分工

- `PageRender`：唯一碰 Android 的那个。建 WebView、挂到宿主 Activity、按静默窗口取字、交回文本加一次读数
  （整页字数、汉字数、轮询次数、取字回值次数、挂载与主文档是否完成、耗时、失败种类）。
- `PageText`：清洗、认墙、挑出该入库的那一段、给它定档。纯函数，一行 Android 都不碰，所以判据能在主机上跑
  `tests/PageTextRegression.java`（120 条，发布前必跑）。真机那一步只负责把 innerText 交回来。

## 三处反直觉（都踩过了）

1. **WebView 只能在主线程建，而且必须挂在一个真有 layout 的宿主上。** 用 application context 建的 WebView
   永远挂不上界面，没有 layout 就没有 innerText：取字回值全空，看起来和"这一页没字"一模一样。
   现在宿主由调用方给（Activity），`Result.attached` 把这件事单独报出来，失败话里单列一种。
2. **`evaluateJavascript` 交回的是"那个 JS 值的 JSON 写法"。** 脚本里写 `return JSON.stringify([...])`
   会被再包一层字符串，按数组解析 74 次全失败，又伪装成"这一页没字"。现在脚本 `return` 数组本身，
   接收端两种写法都接住。
3. **不能等 `onPageFinished` 就交卷。** 万方那一页是 Vue，主文档加载完了数据还在路上：本机
   `--dump-dom` 的虚拟时间预算不够就先交卷，只拿到 457 汉字，FlareSolverr 多等一会儿拿到 3,331。
   手机同样处理：`onPageFinished` 之后每 `pollMillis` 取一次字，连续 `silenceMillis` 不再变化才算写完；
   中途认出是一堵墙就立刻收工，不多等——多等只会让一堵墙看起来更像正文。

| 参数（`PageRender.Options`） | 默认 | 为什么是这个数 |
| --- | --- | --- |
| `userAgent` | 桌面 Chrome 124 | 手机 UA 会拿到 wap 那份更薄的面包屑页 |
| `silenceMillis` | 1,600 | 前端数据请求回来写 DOM 的间隔，比这短会在两次请求之间误判"写完了" |
| `pollMillis` | 400 | 静默窗口的刻度；再密只是多花几次 `evaluateJavascript` |
| `timeoutMillis` | 45,000（探针里每页 30,000） | 一整页的上限，别把用户流量和等待时间耗光 |

## 失败要说清是哪一种

成功只有一种（可读，并带一个档位）。失败八种说法，界面上不许各起一名：

- **要登录（跳到了登录页）** / **滑块、验证码** / **要购买（单篇付费页）**：URL 与页面文本两处都认，
  认墙先于认厚薄。登录页上也有"摘要""关键词"这些字样，那一页一个字都不许入库。清洗会删含"登录"的短行，
  而登录页上"账号登录 短信登录"这种短行既像导航又是证据——所以含墙字样的行不删，且认墙时先拿未清洗的原文认一遍。
- **空壳（页面没渲染出可读汉字）**：清洗后不足 260 汉字。单页应用那个壳正好落在这条线下。
- **太薄（认不出摘要或精要那一段）**。
- **超时**拆成四种说法：没挂上界面 / 主文档始终没加载完（多半网络那条路不通）/ 页面加载完了但取字一次都没回值 /
  取字回了 N 次、最后一次只有 K 个可读汉字。四种的下一步完全不一样。
- **这台手机没有可用的 WebView 内核**（国产 ROM 裁掉或禁用 WebView），不混进"超时"。
- **页面加载失败：`net::错误码`**（只认主文档，子资源失败不算这一页失败）。
- **已取消** / **没有地址或上下文，没开始加载** / **渲染要占主线程转圈，请在工作线程调用**。

## 定档：宁少，不许冒充整篇

`PageText.pick()` 的顺序是 **整页够厚 → 精要 → 摘要 → 退路 → 太薄**：

| 档 | 门槛 | 够不着会怎样 |
| --- | --- | --- |
| `全文` | 整页 ≥ 6,000 汉字 | 万方 3,331、知网 wap 900 都够不着；只有把整篇摊在页面上的期刊官网够 |
| `精要` | 页面里「全文精要」那一段 ≥ 200 汉字 | 万方从整篇自己摘的结构化压缩文本。**这一档不许读成整篇正文**，注记与落库文件名里都写着"精要" |
| `摘要` | 摘要小节 ≥ 90 汉字 | 知网 wap 那份还带着网站自己截的省略号，本来就只配算摘要 |
| 退路 | 整页没有一个"摘要"标题时，取第一个小节表头之前最长的那一段 ≥ 90 汉字长行 | 手机知网 wap 就是这一种：摘要摊在题名下面，下面紧跟"机　构:"、"领　域:"、"关键词:"。仍记摘要档，注记写明这是退路取的那一段 |

整页够厚排在精要前面：够得着正文门槛的页面摊开了整篇，这时候只取那一段精要是把四分之三材料丢掉。

两处口径上的规矩：

- 档位写进落库文件名（`题名·站点·档位.txt`），因为来源榜拿文件名当题名；同一篇从知网和万方各渲染一次落成两个文件，
  正文哈希相同的那条由入库去重挡掉（真机验过：第二次渲染同一页回"库里已有同一篇"）。
- `Picked.chinese` 是取回那一段的汉字数，`Picked.pageChinese` 是整页的。这两个数串过一次：注记把 900 字的页面
  说成"整页只有 90 个汉字"，看日志的人会以为页面是空的。现在注记里两处各写各的，断言钉着。

取回的那一段走的是现成的 `CorpusImport`（与自建库一键批量导入同一条路），档位落 `index.json` 的 `material` 键，
四档的含义与降权规则见 `docs/material-tiers.md`。

## 真机跑法

探针是独立 applicationId（`com.rikkahub.wordlite.pagerender`），不覆盖已装的 Word Lite，也不进发布前的必跑清单
（要真机、要联网、要对家的页面还在）。

```powershell
pwsh tools/build-pagerender-probe.ps1                       # 内置那四个真地址
pwsh tools/build-pagerender-probe.ps1 -UrlFile 清单 -KeepInstalled
pwsh tools/build-pagerender-probe.ps1 -PushList 清单        # adb push 页面，按 file:// 离线加载
pwsh tools/build-pagerender-probe.ps1 -Tree <源码树>        # 树里有别人改到一半的文件时指到自己的快照
adb logcat -d -s WLpagerender                               # 末尾一行 DONE
```

内置四地址与 `tests/BrowserBodyProbe` 同一批：万方详情、维普详情、知网 wap 详情、ar5iv 全文。
探针还会把清洗后的整页文本落到自己的外部目录（`dump-*.txt`），`adb pull` 回来可诊断——
"认不出摘要那一段"这种失败不靠猜。

## 真机实测（EAMUT20528011355，WebView 后台加载）

| 页面 | 整页 | 取字/轮询/耗时 | 判成 |
| --- | --- | --- | --- |
| 知网 wap 详情（渲染后 33,657 字节，`file://` 加载） | 1,324 字 / 900 汉字 | 6 次 / 6 次 / 2,468 ms | 可读 → **摘要档 90 个汉字**（走的是退路：那页没有"摘要"标题） |
| 登录页（文件名 `gate-500.html`，名字里没有 login） | 342 字 / 307 汉字 | 1 次 / 1 次 / 464 ms | **要登录，一个字都不入库**（靠页面内容认出，不靠 URL） |
| ar5iv GPT-4 全文 | 115,533 字 / 0 汉字 | 6 次 / 6 次 / 2,491 ms | **空壳，拒收**（见下面那条缺口） |

入库与比对那一发（清掉探针自己的数据后重跑，回执不是去重）：

    取回 摘要 90 个汉字，落库名 基于多尺度特征融合的水域SAR图像特征配准方法-…-手机知网·摘要.txt
    注记 取的是小节表头之前那一段长文（那一页没有摘要标题）（那一段 90 个汉字，整页 900 个汉字），
          按摘要入库；正文那一节没公开
    入库 1. 已入库 …·摘要.txt（126 字） · 摘要级入库
    自检 抄了取回那一段的第一句：1 处命中 / 108 字 / 分母 254 字，
         来源档 只有摘要可比，正文级 0 字，精要级 0 字，摘要级 108 字
    自检 比对材料：本次比对材料 1 篇（1 组）：自建库 · 只有摘要可比 1 篇

也就是说：手机 WebView 取回的那一段真的进了自建库，真的被 `TextCorpus.match` 检出，
并且这笔命中全记在摘要档、正文档 0 字。

## 还没做的

- **真站地址在这一台手机上没测到**。2026-10-08 那一轮四个真地址一律 `net::ERR_CONNECTION_REFUSED`
  （450–784 ms，挂载成功、主文档"加载完"、取字 0 次），当时 `adb reverse` 没在、WiFi DISCONNECTED、
  5G NR 带 `CAPTIVE_PORTAL`。上面那三行是 `adb push` + `file://` 的读法：渲染→取字→定档→入库→命中自检
  这条链在真机 WebView 上跑通了，"手机能不能连到知网"这一条要靠 `adb reverse tcp:7897` 那条路补测。
- **英文整页判成空壳**。ar5iv 那 115,533 字里 0 个汉字，被厚度门槛拒收——厚度只数汉字，
  拉丁字母与标点撑不出正文。英文这条材料路由开放获取 PDF 那一路负责（`docs/retrieval-recall.md`），
  不为了收它去降这个门槛。
- **万方「全文精要」是否每篇都有**：只对一篇验过。
