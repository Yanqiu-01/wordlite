# 迭代路线（0.4.5 → 1.1.5）

22 个可安装版本，其中 4 个大版本：`0.5.0`（比对内核）、`0.6.0`（检索与自建库）、`0.7.0`（AIGC 内核）、`1.0.0`（报告界面）。每个版本都必须带自己的回归断言、自己的 APK 与自己的 release，禁止只改版本号。

命名沿用现有约定：功能加一版，修复加一位。

## 进度

已发布到 `0.5.3`（`versionCode 24`，`v0.5.3` 带可直接安装的 APK 与 release）。下面表里的条目按实际交付情况对账，与计划不同的地方写在每节末尾的"对账"里，不偷偷改验收标准：

- 0.4.x 三条已全部交付（0.4.5/0.4.6/0.4.7），另加 0.4.4 的排版修复。
- 0.5.0 交付了逐字长串与指纹带；**0.5.1 的"命中按文献聚合"没做**，那一版实际交付的是知网接入与十条检索路各走各路，来源榜挪到 0.5.4 做。
- 0.5.2 交付的是"连不上时把找过的路摊开"（当时排在这条上的事），`byEngine` 只到检索源一级，不是文献一级。
- 0.5.3 阈值标定已交付：`tools/detect-calibration.ps1` 可重跑，拐点与表格在 `docs/detection-calibration.md`，标定语料在 `tests/corpus/`。窗口长度与 winnowing 窗定在 n=7、w=12、三枚共通指纹，句级 Dice 从 0.60 降到 0.55。
- 0.6.0 的真正前提是先修检索覆盖：`EngineSettings.perEngine` 现在一个数兼两职（既是每页条数又是整轮入库配额），中文三库一次就回满 12 条，所以第一个窗口之后所有源都在发请求前被跳过——默认设置下一篇长文实际只检索了开头。这条不修，0.6.x 后面几条都是空谈。

| 1.1.7 | **拼接片段不许只认半句**：1.1.1 的守卫是「多候选片段整段报」，代价是 `merge-pairs` −4 字；正确做法是对过线的前 N 个候选各裁一次再取并集 | `merge-pairs` 与 `spliced` 回到 99.7% / 99.5% 以上，而 `embedding` 的 0 字多报不许回去 |

明确不做，每条都是被实测否掉的，别重新发明：

- **WCopyfind 式带内桥接**（`RUN_BRIDGE_GAP`/`RUN_BRIDGE_PRECISION`）。D3 自己定的前置条件是大模型改写形状的
  实测缺口，而 `local-edit-16` / `local-edit-25` 量出来是 99.5% / 99.8%——疤状局部改动打不动现行判据，桥接不上。
- **按句长加权的 Dice 下限**。直觉是"长句证据多所以可以放松"，实测相反：负例能摸到的最高 Dice 0.358 出现在
  50-80 字长句桶，短句桶只有 0.158。方向反了。
- **把 `SIMILAR_DICE` 一路降到 0.45/0.40**。0.45 多认回约 5 个点，但头顶余量从 0.14 剩到 0.09，
  而真实文库规模下的偶发撞车要吃的就是这一档。等真实文库的负例天花板量出来再说。
- 降重建议太温和（20 段只推 291 字改动，全文 6%）不在匹配这一头解决，排在 1.0.4 的逐条采纳里做。

## 每个版本的固定动作

1. 先写回归断言，再写实现。
2. `pwsh tools/test-host.ps1` 全绿；动到界面或渲染的版本再跑 Robolectric。
3. `pwsh tools/build-host.ps1` 出 APK，`pwsh tools/release-version.ps1 -Version x.y.z` 一次完成升版本、提交、打 tag、开 release 并附上可安装 APK。
