# 随包字库到底带了多少字

2026-10-09 实测。测量脚本口径：读每张脸的 Unicode 映射（`getBestCmap`，也就是 Android 和 java.awt.Font
真正用的那一张），逐码位查有没有带笔画的字形；不用"把所有 cmap 子表并起来"的算法，那种数法会把
字体厂商塞进去的空映射也算成字。

## 一句话

随包 29 张脸里没有一张被裁过。中文正文字库都带到 20,900 个汉字以上（基本汉字区一共 20,992 个），
华文新魏/华文隶书/华文行楷是 6,763 个汉字——就是 GB2312 的全部汉字，这三张脸从设计上就只有这么多。

## 和两个来源逐字比过

拿本机 `C:\Windows\Fonts` 的原件，和 GitHub 上 `chengda/popular-fonts` 的同名字库（华文新魏/楷体/仿宋/
细黑/中宋/宋体/隶体/行楷/微软雅黑，共 10 张，已下到 `artifacts/font-check/gh/`）对：

| 字面 | 随包汉字 | Windows 原件汉字 | GitHub 同源汉字 | 共有码位上字宽不同的 |
| --- | --- | --- | --- | --- |
| 华文新魏 | 6,763 | 6,763 | 6,763 | 0 |
| 华文隶书 | 6,763 | 6,763 | 6,763 | 0 |
| 华文行楷 | 6,763 | 6,763 | 6,763 | 0 |
| 华文楷体/仿宋/细黑/宋体/中宋 | 20,902 | 20,902 | 20,902 | 0 |
| 宋体 | 20,992 | 20,992 | - | 0 |
| 微软雅黑 | 20,992 | 20,992 | 20,992 | 0 |
| 等线 | 20,992 | - | - | - |
| 黑体/楷体/仿宋/幼圆/隶书 | 20,902 | 20,902 | - | - |

字宽逐字比过，一个都不差；unitsPerEm、hhea 升降部、OS/2 typo 与 win 升降部也全一致。所以换字体不会
动分页。GitHub 那几份的字形数比随包多几百个（比如华文新魏 8,159 对 7,848），多出来的那批在自己的
Unicode 映射里根本没有码位指过去，任何渲染器都取不到，换过去只会让包变大、让分页重测一遍。

## 那"少了 15,021 个字"的说法是哪来的

华文楷体/仿宋/细黑/中宋/宋体的 Windows 原件在 Unicode 映射之外还挂着别的子表，里面写着 15,021 个码位：
7,905 个谚文、3,807 个其他区块、89 个 U+9FA6 起的极生僻汉字、若干 C1 控制符（U+0080-U+009F）和
泰卢固文 U+0C21 这类。这些映射在原件里也不指向任何带笔画的字形，换任何渲染器都画不出东西。
按"把所有子表并起来"的数法就会得到"随包少了 15,021 个字"这个假结论。

## 用户那篇稿子实际用到的字

`tests/samples/input-liu.docx` 按每个 run 声明的字体名逐字统计（`(继承)` 走文档默认的 宋体/Times New Roman）：

| 稿子里声明的字体 | 用到的不同的字 | 随包字库缺字 |
| --- | --- | --- |
| 宋体 | 644 | 0 |
| （未声明，落宋体/Times） | 881 | 0 |
| 黑体 | 161 | 0 |
| Times New Roman | 89 | 0 |
| 华文新魏（封面那两行标题） | 22 | 0 |
| ＭＳ 明朝 | 22 | 见下 |

"ＭＳ 明朝"只有"实验室经费充足，开展实验需要用到以下实验药品和设备："这一句用了它。本机没装
MSMINCHO.TTF（日文明朝体只随日文语言包来），所以这 22 个字落宋体，字体对话框里会写"字库没有
「ＭＳ 明朝」，用「宋体」显示"。这是唯一一个真没有本尊的名字。

## 挡住以后少字

`tests/FontSubstitution.java` 第 11 段：逐张脸数基本汉字区画得出多少个字，地板就取上表的实测值再往下
留两三个的余量（华文新魏等三张 6,763，满字的几张 20,900/20,990）。以前只有文件字节数的地板，
一张脸被裁掉两千个字也照样过。
