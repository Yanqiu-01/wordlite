# 改写召回实测：这段字改到哪一档，这台器就开始看不见

回答一个问题：降重把自家查重器的读数压下去那几个点（3.14% → 2.42%），是"真的不重复了"还是"只有这台器认不出来"。本轮只测量、只报数，`DuplicateEngine` / `TextCorpus` / `LocalLibrary` / `CorpusImport` 一个字节没动，阈值一个没调。

复现：

```
pwsh tools/run-suites-private.ps1 -Tree . -OutDir artifacts/agent-paraphrase/out -Suite ParaphraseRecallAudit
```

量台 `tests/ParaphraseRecallAudit.java`（不在 `tools/test-host.ps1` 的必跑清单里，只吃本地语料），词表四份随文件提交：`tests/paraphrase-synonyms.txt`（175 条）、`tests/paraphrase-modifiers.txt`（52 条）、`tests/paraphrase-connectives.txt`（20 条）、`tests/paraphrase-numbers.txt`（18 条）。表里没有随机数：量台自己把 14 档稿子构造两遍并逐字比过；两次独立进程的日志逐字节相同（只有两行"耗时"不同）。

## 1. 一句话结论

- 六个变量里只有**换字**伤得到它：换到 20% 读数一字不掉（100.9%），换到 35% 腰斩到 **52.3%**。调序（含全段倒序）、插虚词、删修饰、数字换写法四种一档都没伤到（90.7%~110.2%）。一个学生拿降重软件过一遍的叠加档剩 **67.7%**——三分之一的抄来字不再被认出。
- 而这些掉下去的字在**整段口径上一直活着**：叠加档整段袋 Dice 0.784（地板 0.72 过线），同一档句级只有 6/12 句过线。第 5 节把它接到 `DetectionFloor` 已有的那组数上：这不是新发现，是同一形状沿六个变量的延伸。
- 三条相似判据里 `SIMILAR_DICE` 先倒下（35% 档只剩 44.1%），`SIMILAR_BAG_DICE` 最后倒下（叠加档还剩 63.0%）；`SIMILAR_CONTAINMENT` 十四档读数与逐字那一路**逐位相同**，边际贡献 0 字——它要长短比 1.6~3.76 倍，而整段/整句改写的长短比≈1。开关自检证过它能收下候选，0 是形状不对它胃口，不是没接线（第 4 节）。
- 对用户的含义：改写过稿子的人手上那个百分比只能当**字面重合的下限**，不能当"没重复"的证明。
- 本轮接着量的那一档写在第 8 节：给"整段兜底"先量一份段落档自己的负例顶，量出来是 **0.865**（一段话里只有一句真引用、整段不是抄的那种形状），比要认的两行改写（0.722 / 0.784）还高——两个分布交叉，这条修法被实测否掉，引擎一个字节没动。

## 2. 量的是什么

自建库走产品入口一（`LocalLibrary.addDocument` → `index()`），四份版本库里已有的材料：`tests/corpus/real-prose.txt`、`tests/corpus/oa-planted-cjmenet.txt`（正文档）、`tests/corpus/oa-abstract-cjmenet.txt`（摘要档）、`tests/samples/input-liu.docx`。入库 4 篇 / 842 句。

**这四个文件不是四篇独立文献**：`real-prose.txt` 就是 `input-liu.docx` 抽出来的正文（125 段逐段能在 docx 里逐字找到）。所以库里同一篇正文存了两份，表 A 的"命中文档数"上天就是 2，它不是召回信号。真正的干扰项只有另一篇论文的 11 句与它的摘要——去掉源段的那份对照库只放这两份（2 篇 / 15 句），**14 档全部 0 字 0 处**：改写没有把稿子推向别的文献，掉的确实是召回，不是噪声。

稿子 = 从 `real-prose.txt` 里按固定规则取的一段（句子数 ≥ 4 且有效字数最长）：**656 有效字 / 12 句**，原样已在库里，所以基线是 656/656 字 = 100.00%、1 处命中。每一档只动一个变量，比例一律按"改动字数占基线 656 有效字"算，位点在整段等距抽（不是从头往后吃）。

| 档位 | 实际动了多少 |
| --- | --- |
| 同义词替换 5% / 10% / 20% / 35% | 18 / 35 / 69 / 122 处，净 +1 / +4 / +6 / +8 字 |
| 调序 两句块 / 三句块 / 全段倒序 | 一字不换，只按 `TextCorpus.sentences` 切句后整块倒装 |

## 6. 降重自己改完的那份稿子：闭环复核的真实读数

判据、预算、基线全照 `RewriteRateRegression`（11 句 OA 正文入库、插进 `input-liu.docx` 当靶子、`RewriteLoop.Limits` 用同一组：rounds 10 / depth 8 / candidates 8 / verifications 240）。下面的数是从 `RewriteLoop.Result` 里取出来的，没有另算一套。

| 读数 | 值 |
| --- | --- |
| 闭环复核（它自己的账） | 改写前 1 处 / 516 字 = 3.14% → 改完还剩 **3 处 / 398 字 = 2.42%** |
| 段落覆盖 | 命中 11 段，改写覆盖 11 段，改完单独比对已无命中 1 段；整篇验证 175 次 |
| 分通道（补充，同一把尺） | 全开 516→398｜逐字 516→**210**｜Dice 516→**398**｜包含 516→194｜袋 516→320 |
| 逐段粒度（改完的段 vs 它自己的原文） | 11 段：整段口径三元组过线 10 段、袋过线 11 段；句级口径 17 句里三元组过线 12 句、袋过线 8 句 |

三点要说：

1. 命中"处数" 1 → 3 不是命中变多：判据把间隔 ≤ `MERGE_GAP` 的命中并成一段，中间段落不再命中就把一条长带裂成几条（`RewriteRateRegression` 里已注明）。分子看字数。
2. **这一档的下降不是器瞎了。** 自家降重打掉的是逐字连续证据（516 → 210，少 59%），可剩下的 398 字全部仍由三元组 Dice 那一路认出（Dice 单开 = 全开 = 398，袋单开 320 没再多认一个字）。也就是说 2.42% 那个数在"改写这一头"是站得住的：字面证据真的少了，而不是只有这台器看不见了。第三方/大模型改写才是另一回事（表 A 的叠加档）。
3. 包含率单开反而比逐字**少** 16 字（210 → 194）：句级命中的落点被 `clipToSharedBlocks` 裁窄之后，指纹带被咬掉的那一段补不出 18 字就整条丢。这就是 `TextCorpus` 注释里 1.1.7 那个"抄得更多、报得更少"的形状，本轮只记录，不动它。

## 7. 先失效的是哪一路

1. **逐字那一档**（`MIN_MATCH=18` 的指纹带 + 整段字面）：同义替换 10% 就只剩 42.1%，叠加档 4.7%。这是定义使然——同义替换要打断的就是连续字面。它不是判据失灵，不许当精度指标用。
2. **三条相似判据里 `SIMILAR_DICE` 先倒下**：同义 35% 档 44.1%、叠加档 58.4%。`SIMILAR_BAG_DICE` 最后倒下：同义 35% 档 52.3%、叠加档 63.0%。顺序在两个档位上一致。
3. **`SIMILAR_CONTAINMENT` 十四档边际贡献 0 字**（读数与逐字那一路逐位相同），结构原因是它要长短比 1.6~3.76 倍；在降重那份稿子上它是负贡献（-16 字，第 6 节第 3 点）。

## 8. 段落档兜底：动手之前先量负例顶（结论：这条被实测否掉了）

第 9 节原来那条兜底只有一个成立条件：**段落档自己的负例顶，要落在"认得出那两行改写"所需的下限之下**。
探针里 `paragraphTierCeiling` 量的就是它。负例分法与句级 0.577 那批同源（`RewriteRobustnessRegression.bagStudy`：
同一份 `real-prose.txt` 奇偶对半分，偶数段当入库、奇数段当没入库——同领域、同一支笔、同一套术语），
再加三批与文库不相干的真人段与一批构造档。每一对先问一次前提：这两段之间有没有一句真的过句级那一线

## 10. 这份实测的边界

- 一段（656 字 / 12 句）、一个学科（宽禁带半导体封装互连）、四张固定词表。这是一个确定样本，不是一个分布。
- 词表是"能不能认出"的自变量，不是改写质量的评价：表里的替换词没有逐条人工校对是否改变命题（"局部→小范围"这类会），测量口径是"字符变了多少"。同义 35% 那一档同时也就是这张词表在这段文字上的池顶（35.8%）。
- 分通道是消融读数，与全开不等价（表 B 已写明三条原因），"三路之和"不作分子。
- 叠加档的四件事按固定顺序叠（数字单位 → 同义 → 删 → 插 → 两句块倒装），换顺序就是另一档；本轮只报这一种叠法。
