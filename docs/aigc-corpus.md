# 标注语料（AIGC 系数标定的第一批真标注样本）

ROADMAP 3.0.0 那条前置门槛的交付物。**系数没有换号**：`AigcScorer.VERSION` 仍是 `v1-order-only`，
`app/src/main/java` 一个字节都没改，本轮只新增语料、说明与测量产物。按 `docs/aigc-calibration.md`
的规矩，"已标定 / `cal-*`"这些词在本文档里也不出现——本文档的档位代号一律用 `H* / M* / X1`，
文件一律用 `aigc-label-*` 前缀，就是为了和"已标定"区分开。

一句话结论先放在这里：**这批语料分不开真人档和机器档，而且方向是反的**。所以它够格当 3.0.1 的
"必须先改判据方向"的证据，但**不够格**当"照这批语料把系数标定掉"的证据。第四、六节分别给数字和缺口。

## 二、每档的来源说明（诚实性条款）

每个语料文件头部都带同一套注释：谁写的、怎么产生的、有没有人工编辑、采集途径、局限。
下面是同一件事的展开。

### H2 真人撰写 · 逐字摘录（多作者）

- **作者**：各篇论文的署名作者，真人。本仓库没有写其中一个字。
- **来源**：仓库里**已有**的检索页快照 `tests/samples/cqvip-search-titled.html`（维普检索结果页静态存档）
  中 `class="abstr"` 的摘要字段原文。不是本轮新抓的，没有新增任何外部来源。
- **采集途径**：脚本 `artifacts/agent-aigc/make-human-verbatim.ps1` 正则抽取。**抽取动作是脚本做的，
  不是人工抄写**——所以 H2 只覆盖"逐字复制的真人文字"这一维，不覆盖"某个人手抄/手改"那一维。
- **改动范围**：剥标签、折叠空白；超过 400 字的条目按整句在句末标点处截断，逐条记录在
  `artifacts/agent-aigc/human-verbatim-manifest.tsv`。没有替换过任何一个词。
- **给不出篇名**：该快照的题名节点在静态 HTML 里是空的，只能回溯到快照文件本身。
- **不能证明**：摘要文体比论文正文更模板化（目的/方法/结果/结论），H2 是"更难的真人负例"，
  不等于正文语料；也无法逐篇排除 LLM 辅助写作，越是近两年的条目这条假设越脆弱。

### H1 / H3 既有真人语料（不重复造）

H1 是从 `tests/samples/input-liu.docx` 抽出的学位论文正文（`artifacts/agent-aigc/extract-docx.ps1`
重跑得到 78 段 ≥120 字的正文段，与 `real-prose.txt` 段数一致），**一位作者**。H3 是知网检索结果页
上 15 条别领域论文的摘要预览截断片段（来源说明见 `docs/detection-calibration.md`），尾部带作者名，
正文被截断。两者都是既有文件，本轮没有改动、没有复制成新文件。

### M-RAW 机器生成 · 未经人工编辑

- **生成者**：本机编码代理（Codex 运行时里的大语言模型），2026-10-08 一轮会话内成稿。
  **它不是任何商用产品化模型的导出文件，也没有从任何网站采集**——这条按硬性要求写进文件头，
  任何人不得把这一档读成"某商用模型的输出"。
- **指令**：每段一次自指令，形式只有"写一篇关于 X 的论文正文段落，约 250 字，中文"。
  没有文体提示词，没有模仿/规避要求。逐条记录在 `artifacts/agent-aigc/machine-prompts.txt`。
- **人工编辑**：无。没有真人读过并改写。成稿后只跑机械校验（每段一行、数字数），
  没改过用词、句式、标点，没有在候选之间挑过，没有第二稿。文件里留着"道路提取在提取过程中"
  这类一次成稿的别扭处，它们正是"未回改"的证据。
- **污染（重要）**：写这些段落的同一个代理在写之前读过 `AigcScorer.java` 的注释，那里点名了套话词
  与真人侧触发率。这一档带着"知道考卷"的污染，只能当弱标签。
- **事实性**：段里的数值、型号、机构、结论全部编造，不指向任何真实研究。只能用于文体测量。

### M-EVADE 机器生成 · 提示词要求"写得像真人"

同 M-RAW，只是指令多两句："不用总分总列举、不用综上所述/首先其次一类连接词、长短句不匀、
允许保留限定语和没把握的说法"。这一档测的是**机器被要求规避风格检测时**的表现，属对抗情形。
副作用要在读数时记住：模型被要求"像真人"之后明显过度纠正——段落变短（122-197 字，偏离 150-400
的目标尺度）、句子变碎、出现口语词，这本身就是另一种可检测的破绽，但本档不因此更好用。

### X1 边界档：真人原文 + 代理轻度润色（无真人参与）

- **底本**：`tests/corpus/real-prose.txt` 第 1/2/4/5/6/8/9/10/11/12/13/14/16 行（`real-prose.txt`
  一字未改，底本仍在原处），对照表 `artifacts/agent-aigc/human-polish-agent-manifest.tsv`。
- **编辑者**：编码代理。**没有任何真人参与改写**，所以这一档既不是"机器生成后人工改写"，
  也不是"真人轻度改动"，它是"真人内容 + 机器表面改写"。
- **规则**：只调语序、换连接词、拆并句子；数值、单位、引用标号、材料牌号、术语照抄底本。
- **为什么必须有它**：这是这个 App 真实用户最可能提交的形态（自己的段落丢给模型润一遍再交）。
  它不属于纯真人也不属于纯机器，混进任何一侧都会污染标定，所以单列一档。

### 明确没有做的档位

- **"真人逐字抄写 / 真人轻度改动"档：本轮没有做，也不是忘了。** 这一档要求一个真人执行抄写或改写
  动作。代理无法诚实地产出它，而伪造一份（把代理产出写成"某人抄写/编辑"）是本轮明令禁止的事，
  所以宁可不建这个文件。缺多少见第六节。
- **"机器生成后人工改写"档：同上，需要真人编辑，没有做。**
- **"商用模型输出"档：没有做。** 本仓库没有任何商用模型的导出记录，写不出来就不写。
## 三、格式与标定台对齐（新语料能被现有标定台直接吃下去）

读数口径抄的是 `tests/AigcCalibrationSweep.java` 的 `load()`：**一行一段**，`#` 开头与空行跳过，
`TextCorpus.normalize(text).length() < 120` 的行丢弃。新语料完全按这个口径写，没有另造标注格式：
标注信息全在文件头的 `#` 注释里（标定台天然跳过），一条一段，段内不带任何标记符。

跑法（脚本只调用不改，`-Classes` 另起一份干净 class，避免读到主线旧 class 的数；
`-Out` 指到 `artifacts/agent-aigc/`，**不覆盖主线的 `artifacts/corpus/aigc-sweep.txt`**）：

```
pwsh tools/aigc-calibration.ps1 -Corpus tests/corpus/aigc-label-human-verbatim.txt `
    -Out artifacts/agent-aigc/rigs/aigc-label-human-verbatim.txt `
    -Classes artifacts/agent-aigc/build
```

跨档一次跑完用 `pwsh artifacts/agent-aigc/tier-baseline.ps1`（它只是循环调用上面那条命令，
再从产物里抽 `CORPUS` / `LEGACY` / `FPB` 三行拼表），逐句分数与跨档 AUC 用
`artifacts/agent-aigc/AigcLabelProbe.java`（只读探针，不覆盖系数，`detect` 走产品默认表）。
**探针与标定台逐位相等**（7 个档的 mean / max / over-0.45 全部一致），所以下表既是对标定台的
复读，也是对它的交叉校验。

一个必须记住的读数陷阱：标定台一次只把 `-Corpus` 那个文件当被测侧，M2 是它拿骨架表**拼这个文件**
现造出来的。所以 `artifacts/agent-aigc/rigs/aigc-label-machine-raw.txt` 里的 `machine2` 列是
"机写稿拼机写稿"，没有意义；主线的 M2 数字一律取 `rigs/real-prose.txt` 那一次。

## 五、这批语料能证明什么、不能证明什么

### 能证明（都有上表数字支撑）

1. **v1 判据的方向对真实机写文本是反的。** 真人合并池 440 句 vs 机器合并池 227 句，
   按"机写应更高"换算的 AUC 是 **0.305**；机器侧最高句分 0.217，连 0.35 的合并下限都没碰到。
   默认写法（M-RAW）和被要求规避风格（M-EVADE）两种机写都是这个方向，后者更反（0.249）。
   这条直接决定 3.0.1 的次序：**先修判据方向，再谈系数数值**；否则换任何一组数都是在反向刻度上调表。
2. **"真人侧零误报"不成立，它是单作者语料的产物。** 换成 20 组作者的逐字摘录档 H2，
   `margin` 从 H1 的 +0.084 变成 **−0.056**，1/113 句越过 0.45，6/113（5.3%）过 0.35。
   `docs/aigc-calibration.md` 里"爱写排比的作者会被冤枉，这个比例现在无法量化"那句话，
   第一次有了可引用的数（尽管是很粗的第一版）。
3. **既有 M2/M3 的高分来自构造同源，不是召回能力。** M-RAW 与 M3 是两个不同总体
   （AUC 0.242），H2（真人）与 M3 的分布已经咬在一起（AUC 0.417）。用 M2/M3 验召回是自证。
4. **表面风格特征对"AI 润色过的真人稿"没有区分度。** X1 与真人池的 AUC 是 0.488（就是分不开），
   而 X1 离机器池有 0.266 的距离。这个 App 真实用户最常提交的正是 X1 这种形态。

### 不能证明（读这批数字时必须一起读）

1. **不能证明"代理生成 ≈ 商用模型文风"。** M-RAW / M-EVADE 是编码代理在一个工程会话里写的，
   主题分布、句长偏好、术语密度都带着编码代理的痕迹；换一个 RLHF 版本、换一套中文训练集，
   分布就可能不同。这批样本只支撑一句弱结论：**至少有一类真实 LLM 生成的学术中文，
   现有判据给分低于真人正文**。它不支撑"所有模型都低"，也不排除某个模型在这套特征上得高分。
2. **不能证明污染无害。** 生成者读过 `AigcScorer.java` 的注释（套话词与真人侧触发率都在里面）。
   "知道考卷"理论上会让生成结果更避开特征，也就是说 0.305 这个反向程度**可能被动夸大**。
   要定论需要一轮无仓库访问的干净生成（见第六节第 6 项）。
3. **样本量撑不起稳定分位数。** H2 只有 113 句，p99 实质上是第 2 高值；机器池 227 句。
   AUC 没有给置信区间，跨档差 0.05 以内的比较不要当结论用。
4. **量不到文档级。** 4.3 那张表基本全是"样本不足"，这是 400/200 字 + 连句双门槛在段落级
   样本上的必然结果，不是"检测不到"。
5. **英文族零增量**（本批全中文），`v1-order-only+latin-derived` 仍然没有语料。
6. **没测抗改写攻击**（M1 那类规则改写稿），也没测中英混排（`MIXED_DISCOUNT` 仍是 1.00）。

## 六、够不够支撑 3.0.1 换系数

**不够。** 但够格挡一次：它证明 3.0.1 现在不许按现判据换号，因为方向是反的。缺的档与数量：

| 缺什么 | 缺多少 | 为什么必须有 |
| --- | --- | --- |
| 商用模型输出（带导出记录） | ≥ 2 个模型 × 40 段（150-400 字） | 现在的机器档只有"编码代理"这一个总体，无法泛化到用户实际用的工具 |
| 多作者论文**正文** | ≥ 10 位作者 × 5 段 = 50 段 | H2 的越线条目必须在正文文体上复现或证伪；摘要求不能代替正文 |
| 真人逐字抄写 / 真人轻度改动 | ≥ 20 位操作者 × 2 段 = 40 段（抄本、改动本各一） | 决定"改过的真人稿"会不会被冤枉；本轮代理无法诚实产出，故空缺 |
| 机器生成后人工改写 | 20-40 段 | 与 X1 合起来才能把"谁动的手"这一维拆出来 |
| 整节级样本（≥1500 字/篇） | 每档 ≥ 10 篇 | 否则 4.3 的档位表永远是"样本不足"，双门槛的用处量不出来 |
| 无仓库访问的干净生成 | 20-40 段 | 界定"知道考卷"这个污染的方向与量级 |
| 英文正文（真人 + 机写） | 40 + 40 段 | 拉丁族现在只有平移，没有任何语料 |

对 3.0.1 的具体建议：拆成两步。**3.0.1a** 只补表里前两档（商用模型输出 + 多作者正文），
把 H2 的越线与 M 池的反向在新语料上复验一次；**3.0.1b** 才做逐特征 ROC 拐点与 `version()` 换号。
另有一条不依赖补料的结论可以直接用：**任何新系数都必须让 M 池（真机写）的分布不低于 H 池**，
建议把这条写成标定台的硬判据（`AUC(H,M) < 0.5` 即判该候选系数表不合格），
否则换号以后 p99/max 这类数字仍然可能在反向刻度上越调越糟。

## 九、逐特征方向审计（把 4.2 那条结论拆到 11 条特征上）

跑法只有两条，都不改判据；第二条已经接进回归，缺语料一律失败，不许静默跳过：

```
pwsh tools/test-host.ps1            # 看 AigcFeatureAuditRegression 那一行
```

口径与 `AigcDetector.detectInto` 逐行同序，只是把 11 条特征的**原值**（不是命中与否）也留下来。
真人池 = H1 + H2 + H3 + **X1** = 493 个计分句，机器池 = M-RAW + M-EVADE = 227 句。把 X1 算进真人侧

读表两条：

1. **中位数这一栏在两侧全是 0.000，没有区分力。** 触发最凶的 DIVERSITY 也只在一到两成的句子上触发，
   过半句子根本不触发，所以中位数一律是 0。两侧的比较只能看均值和 AUC，看均值还要注意它是被触发率
   乘出来的（真人侧 PARALLEL 触发率 21.3% 对机器侧 4.0%，这才是"反"的实底）。
2. 符号分布：反 **4** 条，分不开 **4** 条，死特征 **2** 条，方向为正 **1** 条。反的 4 条集中在节奏组与
   词汇组，正是那两条"每千句触发 150~243 次"的老嫌疑（docs/aigc-calibration.md 的反证基准表）。

**决定：走"保留 11 条 + 拒绝给数"，不走"抽一条正方向特征出可疑句排序"。** 三条理由，按证据强度排：

1. 11 条里只有 1 条方向为正（BURST，AUC 0.618），验证率 1/11。BURST 是文档级证据回灌到句的
   句长突发度，它的正方向只建立在"机器侧触发率 44.5% 对真人侧 18.7%"这一对上；而机器侧自己就散得厉害
   （M-RAW 对 M-EVADE 0.679，M-EVADE 对漫画稿 M3 只有 0.187），0.618 经不起换一个生成器再验一次。
2. BURST 与三条方向为负的特征同属节奏组（`AigcFeatureId.group`），而打分是组内取最强
   （`AigcScorer.score`）。同组里一条正证据随时能被一条负证据顶替，句分就不是那条正方向的了，
   排序随之漂移——这种排序写进报告复现不了。
3. 拿 1/11 的验证率去出一个"看着像刻度"的相对排序，就是 2.1.1 发布说明里已经撤回过的那类数。
   一个诚实的"量不到"比一个在样本里的漂亮排序值钱。

因此这一轮的对外后果是**拒绝**，不是**换一种给法**，落点见第十节。要把它换回相对排序，门槛写进了
`tests/AigcFeatureAuditRegression`：方向为正且两侧都有触发的特征要不少于 11 条的四分之一（现在 1 条），
那条断言会先炸。

## 十、未标定在对外那一头意味着什么（0.7.2）

系数一个没改（`AigcScorer.VERSION` 仍是 `v1-order-only`），改的是**没资格给数的时候还印不印数**。
唯一开关是 `AigcScorer.calibrated()`：只认版本号 `cal-` 前缀。想看到数，只有把 VERSION 换成 `cal-*`
一条路，而那会立刻撞 `AigcFeatureAuditRegression` 钉死的 VERSION 字面值。降级做法抄的是本仓库既有的
两条纪律：未完成查重不印 0.00%（`DuplicateEngine.aigcTrend` / `CheckReport` 的未完成头部），
可比对字数不足不给比例（`AigcDetector.MIN_DOCUMENT_CHARS`）。

| 出口 | 未标定期间 | 谁钉住 |
| --- | --- | --- |
| `AigcDetector.verdict` | 只说方向 + 两侧实测数字，不给生成比例；档位那五句留在 `measurement()` 里 | `AigcRegression.guards/tiers` |
| `DuplicateEngine.aigcTrend` | `判据未标定（方向实测为反：真人句分比机器句分更高）` | `ApiRegression.aigcTrendCell`、`DetectRegression.reports/unfinishedReport` |
| `DuplicateEngine.aigcScoreLine` | 空串，指标区那一格连名字一起不画 | 同上 |
| `CheckReport.aigc` 每句那一列 | 倾向分整列撤掉，并写明"顺序是原文顺序，不是可疑度排序" | `AigcFeatureAuditRegression`、`DetectRegression.unfinishedReport` |
| `ApiWorkflow` 结果面板 | 行首 `35%` 撤掉，标题从"倾向较高的句子"改成"触发过判据的句子" | 面板那句由 `ApiRegression` 钉同源文案 |
| `ReportStore.recordFor` | `aigcScore` 落 0，未量到的记录里不留句分 | `AigcFeatureAuditRegression` |
| `ReportCenterUI` 指标卡注脚 | 不印"机器腔可疑 N 个" | `ReportStore/ReportCenter` 存档回归 |

`AigcDetector.Result.rate`、`Tier`、`flaggedChars` 一律照旧计算——判据本身一条没动，动的只是
"现在还不该说出口"这一层。方向哪天被新语料验正，把 VERSION 换成 `cal-*`，上面这些出口原样回来。

### 一条容易记错的数

4.3 节那句"H2 是 6/20 段"是**把双门槛全撤、门槛压到 0.35**（`TIER gate=0.350 run=1 chars=0`）时的
文档级读数。按产品口径的 `SEGMENT_FLAG_GATE = 0.45`，H2 是 **1/20** 段含过线句（那一句 0.506），
H1 是 0/78。两个读数说的是同一件事——真人侧一换作者 margin 就变负——但引用时别把 6/20 安到
0.45 门槛上，那是把误报率说大了一倍。
